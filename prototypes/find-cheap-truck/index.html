用车需求为什么不会把平台做重需求和运力一样，只是信息。平台做的是按线路 / 时间 / 装备 / 吨位推荐，推荐理由透明展示，成不成由双方电话决定；平台不派单、不接单、不确认成交、不定价（预算是货主自填，旁边永远是市场参考而非平台指导价）、不收信息费。司机查看货主电话与货主查看司机电话完全对称：实名 + 车辆认证 → 风险提示 → 留痕 → 反馈。需求有自己的自动失效机制（装车时间到 / 已找到车 / 司机反馈"已找到车"≥2 / 24h 确认），不需要人工维护。红线：三端任何页面不出现"抢单 / 接单 / 平台确认成交 / 代收运费"。
v0.4 · 为什么是"意向 + 先打给谁 + 结果反馈"，而不是"司机报价 → 商家选一个 → 完成互评"竞价链路的四个问题：多司机盯一条需求报价必然互相压价，而顺路车司机是最稀缺的供给；"商家选一个"一旦被平台记录就是平台确认成交，爽约、放空、货损的责任随之进来；钢材用车的装卸等待、吊车、回单、结算周期在报价框里说不清，两句电话就清楚；互评需要平台判定"完成"，又是一层确认，且钢材圈子小、双向评分很快被"给差评就不合作"架空。但它想解决的两个痛点是真的：货主拿到推荐名单后不知道谁有意向要挨个打；司机打完没谈成没有闭环，大家空等。所以综合为：司机一键「有意向」（可选填参考价，标注"以电话为准"，货主看不到别人的价，不排序、不比价、不锁定，24h 过期，一条需求最多 5 位）→ 货主在「我的需求」看到谁有意向、大概什么价、悟运履约如何，决定先打给谁（只是联系顺序，不是选定）→ 电话 / 微信谈定后点「已找到车」（可选勾是哪位司机，其余有意向司机收到 D8 通知不再等；平台不据此确认成交）→ 联系结果反馈替代互评：货主侧 如约到车 / 没谈成 / 爽约 / 坐地起价 / 信息不实，司机侧 如约装车 / 没谈成 / 放空 / 压价 / 信息不实——结构化选项、只在真实联系过的双方之间、不打分、不公开，负面项累计进入现有的核验 / 黑名单，不需要平台判定"完成"。微信在电话之后由双方自行加，平台不做名片交换，留痕与黑名单才不会被绕过。

钱永远不经手。不收运费、不代收代付、不结算、不开运输发票、不收保费。
身份司机实名 + 人脸；车辆行驶证核验；一车一账号；复用悟运履约数据作为公开信用。不做证件分级（"四证齐全"之类）、不做司机等级体系、不代替货主做尽调。
工具运输协议模板（双方自行签）、货运险入口（保险公司承保出单）、联系前风险提示。不做平台担保、不做先行赔付、不做纠纷调解与责任认定。
人工举报处置（恢复 / 下架 / 封号）、自动核验不一致的兜底复核、黑名单。不做运力监控大盘、不做规则开关面板、不做参考价人工校准、不做客服介入交易。
出口货主明确要"有人负责、要发票"时，跳转到合作的持牌网络货运平台（既有规划 L2 档）。货袋子自己不持牌、不承接。

信任由四件系统自动完成的事解决：真人真车核验、悟运真实履约数据、信息自动失效（到期 / 24h 确认 / 反馈隐藏）、联系留痕。任何一项需要人工持续投入的设计，都视为"做重"的信号。

命名 主名"找顺路车"点明来源与便宜的原因，副标题解释车从哪来

找顺路车 已采用一个词说清"为什么便宜"（车本来就要走这条路），不承诺价格、不像交易，符合"只做信息互动"的定位；与"找钢材"同构；副标题"返程车 · 闲置车 · 专装钢材"解释来源。
找特价车（原方案）价格钩子强，但"特价"像平台定价与促销，容易让人以为平台在卖运输服务，与不做承运人的定位不符，故弃用；卡片上保留"特价 -N%"的市场价对比标签。
回头车行业口语，司机和老货主一听就懂，但覆盖不了"闲置车"；可作为返程车类目名。
顺路钢运强调钢材专用与顺路属性，品牌感更强，但价格钩子弱。
捡漏车 / 省钱车更口语、传播性好，适合活动与朋友圈海报标题，不建议做正式功能名。

三个问题的判断 详细分析见同目录 README.md

Q1驾驶员会愿意上来发布吗？

会，但有条件。司机已经在微信群、信息部、满帮找回程货，他愿意多发一个地方的前提是：①这里真有货主看（货袋子买卖双方本来就是钢材运输需求方，而且是"货主直接打电话"而不是黄牛转手）；②发布成本几乎为零（卸货后一键发返程、复用上次、语音说明）；③免费不抽佣；④看得见反馈（曝光、来电、订阅这条线路的企业数）。
  • 冷启动不靠拉新司机，靠悟运存量司机 + 运单卸货节点自动提示，把"发布"变成运单流程的一个顺手动作。
  • 货主侧的"订阅线路"和"发布用车需求"把需求信号反向推给司机："这条线路有 12 家企业在等车"。
  • 风险：信息部 / 黄牛冒充司机批量发布。用一车一账号、定位一致、悟运履约和信息有效率去压制，并给真司机"个体车主"标识。
结论：司机不会为"一个新平台"上来，会为"卸货后 10 秒多一条免费回程货线索"上来。产品重点不是拉新，而是把发布嵌进悟运运单，并让每条发布都有可见的反馈。

Q2找车方会不会担心有问题？

一定会，而且这种担心是合理的：一车钢材货值 10～15 万元，行业经典风险是骗货、放鸽子、坐地起价、货损。找车方真正在问的是三件事：这个人是真的吗、这条信息还有效吗、出事有没有人管。
  • 真人真车：实名人脸 + 行驶证核验 + 车辆照片 + 一车一账号 + 定位一致，做到"比微信群里陌生司机可信得多"。
  • 信息有效：自动到期、24h 确认、反馈驱动隐藏、信息有效率，做到"打过去基本有人接、车基本还在"。
  • 有人管：联系留痕、举报处置、黑名单、提供联系记录；同时把风险动作前置为"三件事"——核人车证、签协议模板、投货运险。
结论：找车方的担心不能靠"平台担保"解决（那会把货袋子变成承运人），而要靠核验 + 透明 + 留痕 + 工具四件系统自动完成的事，把陌生交易的风险降到与"熟车"相当，同时明确边界。这四件事都不需要平台碰钱、碰单，所以能在"轻"的前提下解决信任。

Q3万一车子出了问题怎么办？

先讲清法律与商业边界：平台不签运输合同、不收运费、不派单，就不是承运人，货损、事故、丢货的赔偿责任在司机 / 车队（《民法典》承运人责任），平台承担的是信息服务者的合理审核与协助义务。对应地，平台要做的是：
  • 事前：核验准入、风险提示强制阅读、协议模板（明确运费、时效、货损责任、回单）、货运险入口（保险公司承保出单，平台不收保费不做代理）、装车时人车证核对指引与提货凭证只交给核对无误的车。
  • 事中：司机可授权开放在途定位（车载定位标识）；异常可在平台标记（放鸽子、失联）。
  • 事后：提供联系记录、发布信息、核验结果等凭证协助维权；举报核实后封号并联动悟运账号；严重者报案配合；纠纷案例沉淀为司机信用。
  • 升级路径：当货主明确要"有人负责、要发票"时，进入既有物流规划的 L2 档——接入持牌网络货运平台做合作承运，由其承担承运人责任，货袋子仍不自持牌照。
结论：不承诺"平台赔"，承诺"平台核验、留痕、协助、处置"，并把保险和协议做成一键工具。这样既守住信息平台边界，又让货主在出问题时"有据可查、有人可找、有险可赔"。
