# AI 货袋子获客系统 · 高保真交互原型

对应设计文档 [`docs/ai-acquisition/`](../../docs/ai-acquisition/README.md)（尤其是 [06-前端页面设计](../../docs/ai-acquisition/06-前端页面设计.md) 与 [08-采购方线索渠道](../../docs/ai-acquisition/08-采购方线索渠道.md)），按 06 分册 §13 的优先级实现：看板 → 会话工作台 → 自然语言任务 → 跟进流程编辑器 → 线索 → 话术库 → 开通向导 → 海报分发 → 渠道 / 设备 / 风控 → 触达 / 审核 / 跟进待办；v8 起按决策 Q10–Q16 增加 **线索渠道目录、项目线索、企业档案、线索投喂箱、介绍人与分成、销售企微 H5** 六个页面，并把电话（人工拨打）节点接入 SOP。

纯前端静态页面，**无构建、无依赖、无后端**。所有数据与 AI 行为都在浏览器本地模拟。

## 视觉规范（v8 · 钢铁行业扁平化）

- **色板**：钢蓝 `#1b4f8a`（主色 / 可点击）、炉火橙 `#e8590c`（高意向 / 电话 / 关键动作）、炭黑 `#1c2430`（侧栏 / 强调块）、冷灰 `#eef1f4`（页面底色）；语义色成功 / 警告 / 危险各一档，AI 相关用弱紫底。
- **扁平**：无渐变、无投影（遮罩层除外）、圆角 6 / 4 px、1 px 分隔线；图标统一为线性 SVG（`App.icon(name)`），不用彩色 emoji。
- **直观**：每页固定「标题 + 一句话说明 + 主操作」页头；列表页左侧筛选、右侧详情抽屉；状态只用「标签色 + 文字」表达，数字优先用大字统计卡。

## 打开方式

因为页面通过 `<script src>` 加载共享模块，建议用任意静态服务器打开（直接双击 `file://` 也能用，但部分浏览器会限制 localStorage）：

```bash
cd prototypes/ai-acquisition
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080/index.html
```

入口页 `index.html` 有推荐演示路线、页面清单与所有深链接。

## 演示约定

- **角色**：右上角可在「管理员 陈总」与「销售 张三」间切换（存于 `localStorage acq:role`）。销售视角只显示看板、会话工作台、线索 / 项目 / 企业、投喂箱、跟进待办、审核、介绍人、企微 H5，数据按归属人过滤。
- **数据**：首次打开时由 `shared/data.js` 生成并写入 `localStorage`（键 `acq:state:v8`；报价工作台独立为 `acq:quote:v1`）。页面上的操作（接管、发送、审核、发布流程、创建任务、投喂入库、记录通话……）都会持久化；右上角「重置演示数据」可恢复初始状态。
- **AI 行为**：`shared/engine.js` 以规则优先、LLM 语义兜底的方式模拟意图识别与话术匹配，并给出来源与置信度；投喂抽取按内容类型给出字段 + 置信度 + 问题提示。没有任何网络请求。
- **三层线索模型**：线索表 `leadType = PROJECT | COMPANY | PERSON`；项目 / 企业各有独立页面与评分，联系人可从项目部 / 企业一键转为个人线索并进入 SOP；`platform = GOV | DATA | PHONE` 的线索只能电话 / 线下触达，不走消息触达。
- **硬约束在原型中可见**：
  - 每条消息必须含 ≥ 1 个个性化变量，否则报 `ACQ-2001` 并拦截（任务试运行、向导测试跑通、线索「立即触达」、话术编辑预览均可复现，样例为无昵称的 L012 / 测试线索第 5 条）。
  - 敏感词 / 平台规范报 `ACQ-2002`（如小红书文案含联系方式）。
  - 客户表达拒绝 → 自动进黑名单并终止流程；报价 / 合同 / 承诺效果类话术 → 转人工并进入审核队列。
  - 账号按平台 / 档位限速（养号期 20% / 50% / 100% 额度），被限制即熔断，需人工恢复。
  - 「抓取他人公开评论」默认关闭，开启需勾选风险告知；相关抓取规则受总开关约束。
  - 电话节点不自动拨打：到期未拨按「未接通」分支走；投喂内容必须人工确认后才入库；介绍人分成只记账不自动打款。

## 执行端 App 原型说明

`app.html` 对应决策 Q2（自研 Android 获客助手 App）与 02 分册 §4 / 05 分册 §2.2–2.3，演示要点：

- **绑定与治理**：权限自检（无障碍 / 电池优化 / 通知 / 悬浮窗 / 自启动）→ 扫码或 6 位配对码 → 服务端签发设备 JWT → 检测本机已登录账号纳入托管 → 技能包自检。
- **拟人化执行器**：每条指令按服务端下发的 `pacing` 执行：截断正态采样的等待、唤起目标 App、按昵称搜索、逐字输入（含删改）、发送、截图存证、回执；抓取类指令展示滚动读取与关键词初筛。
- **消息监听**：上报 `INBOUND_MESSAGE` 后，由服务端匹配话术决定是否下发自动回复（拒绝词 → 黑名单不回复；需人工 → 审核单 + 过渡话术；未命中 → 转人工）。
- **投喂**：拍铭牌 / 拍名片 / 语音速记 → `INTAKE_UPLOAD` → 服务端 OCR / 抽取 → `INTAKE_EXTRACTED`，补齐缺失名称后可在手机上确认入库，或交后台投喂箱确认。
- **风控信号**：滑块验证 → `RISK_SIGNAL CAPTCHA_SHOWN` → 账号 NEED_VERIFY，需在手机上处理后点击恢复；微信升级导致控件缺失 → `UI_CHANGED` → 该平台指令暂停 → 技能包更新后恢复。
- **可靠性**：断网离线暂存、重连补传；服务端重发同 `cmdId` 被幂等忽略；低电量 / 非 Wi-Fi 上报后服务端降配。
- App 与后台原型共用演示数据：App 发出的消息会出现在「触达记录」，风险信号出现在「风控 → 风险事件」，设备心跳出现在「触达账号与设备 → 设备」，投喂记录出现在「线索投喂箱」。

## 推荐演示路线

前半段看「项目 / 企业线索从哪来、怎么打（Q10–Q16）」，后半段看「消息触达与自动跟进」；第 0 步是爆品方向的核心动作「秒报价」。

0. 销售：`quote.html?rfq=Q1` 李工 13 吨零碎单 → 看 A–F 方案（Φ20 搭拼车、Φ12 平台直发）、守门原因（客户提老价格）→ 调价 → 确认发送 → 报价记录里「模拟客户接受」看出库 / 采购 / 拼车任务；再看 `?rfq=Q5` 5 吨无车被推荐自提 + 替代规格，`?rfq=Q4` 新客户 50 吨被信用 / 起订量守门；`?tab=rules` 改目标毛利即时重算。
1. 管理员：`sources.html` 看六族 30 条渠道的可获取性等级与获取方式；打开「施工许可」看订阅城市、成本、评分与抓取日志，试着启用一条 C 级渠道。
2. 管理员：`projects.html?open=PJ1` 看「智能装备产业园二期」的中标 + 施工许可 + 桩基进场三信号叠加、用钢量估算与采购窗口；点「电话」记录一次通话，观察阶段与线索联动。
3. 销售：`mobile.html` 右侧「SOP 电话节点」推送 → 点横幅深链到李工 → 打电话 → 按开场白拨打并记「接通」→ SOP 自动置高意向并通知；再试「拍铭牌」→ OCR → 抽取 → 确认入库。

7. 管理员：`jobs.html` 输入「每天早上 9 点抓取抖音评论区求推荐的线索并首触」，看解析与试运行。
