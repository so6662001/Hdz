# AI 企业经营海报生成 · 设计方案

> 需求：在"行情海报"之外，为商家提供**企业经营类海报**的生成能力——用户上传素材库、输入一段需求提示词即可生成海报，再用自然语言反复微调；同时支持 H5 与 PC。
> 本文回答：做成什么样（产品）、用什么模型（选型）、怎么生成与微调（技术）、怎么落地（路线）。
> 配套高保真原型：`prototypes/ai-poster/`（`pc.html` 工作台、`h5.html` 手机端、`poster.html` 原图导出）。
> 模型信息截至 2026 年 9 月，价格与能力以各厂商官网为准，方案中已做"可替换"设计。

---

## 0. 一页结论

1. **不做"一句话直接出整图"，做"大模型设计 + 引擎排版 + 图像模型出视觉"的三层结构。** 企业海报里的电话、价格、企业名、二维码、日期一个字都不能错，纯文生图模型（即便 2026 年最强的）在中文小字上仍有 2%~10% 的错误率，且不可编辑、不可微调。把"精确信息"交给渲染引擎、把"设计与文案"交给大模型、把"视觉氛围"交给图像模型，三者各司其职，海报既好看又零错字、且每一处都可继续改。
2. **模型选型：国内合规优先，一主一备，可路由。**
   - 理解 / 设计 / 文案（多模态 LLM）：**主选豆包 Seed 2.0 Pro（火山引擎）**，备选 **通义 Qwen3.5 Plus（阿里云百炼）**；纯文案改写降本用 DeepSeek V4 Flash。
   - 视觉生成 / 编辑（图像模型）：**主选 Seedream 5.0（火山引擎）**，备选 **Qwen-Image 2.0（百炼，局部编辑最强、可私有化）**；海外版或对小字要求极高的场景可路由到 Nano Banana Pro / GPT Image 2。
   - 抠图 / 超分 / 内容安全：用专用小模型或云 API，不用大模型。
3. **微调 = 大模型对"设计 JSON"做增量修改，不是重新生图。** 用户说"字大一点、换成红色、电话改成 138…"，模型输出 JSON diff，引擎秒级重渲染；只有涉及视觉氛围（"换个背景""更喜庆"）才调用图像模型局部重绘。这样微调快（<2s）、便宜（<¥0.02）、可撤销（版本树）。
4. **素材库是品牌一致性的来源**：Logo、门头 / 厂房 / 产品照片、资质证书、人物照、企业信息（名称、电话、地址、主色）一次上传，生成时由多模态模型"看图选图"，抠图与色彩提取自动完成。
5. **成本可控**：一次完整生成约 ¥0.25~0.45（其中图像 ¥0.2~0.3、LLM ¥0.03~0.1），一次文本微调约 ¥0.01~0.03。按商家月均 30 张、微调 3 次 / 张估算，单商家月成本 <¥20。
6. **落地三阶段**：MVP（高频三大类场景 + PC/H5 + 文本微调）→ 增强（视觉微调 / 局部重绘 / 品牌 kit / 模板沉淀）→ 规模化（批量、团队协作、A/B、行情海报与经营海报统一）。

## 1. 需求理解与场景

### 1.1 "企业经营类海报"覆盖什么

钢贸商家在行情之外，日常会发的海报按"发给谁、为了什么"归为 **6 大类 37 个场景**（原型 `AP.SCENES` 已全部内置，均带关键词识别、默认版式 / 风格、示例提示词与文案模板）：

| 大类 | 场景（37） | 频次 | 典型素材 | 默认版式 | 对"精确信息"的要求 |
|------|-----------|------|---------|---------|-------------------|
| **A. 产品与货源** | 新品上市、到货通知、产品特色 / 卖点、主营目录、库存资源表、加工服务、物流配送 | **高**（每天 / 每周） | 产品图、钢卷 / 仓库图 | split / hero / list / **table** | 极高（规格、钢厂、价格、吨位） |
| **B. 现场与实力** | 仓库发货现场、加工现场、客户接待 / 陪同参观、工程案例、企业实力、资质荣誉、签约合作、团队风采 | **高**（现场类几乎每天有） | **当天实拍**（装车、车间、来访合影、工地）、证书 | **photo / gallery** / split | 中（吨位、车数、项目名） |
| **C. 促销活动** | 特价促销、节假日促销、周年庆促销、限时秒杀、清仓甩货、拼单团购、开业乔迁 | 中高（按活动） | 产品图 | hero / list | 极高（价格、立减、期限、门槛） |
| **D. 品牌与关系** | 节日祝福、节气日签 / 早安、客户感谢 / 服务承诺、客户见证 / 好评、中标 / 成交喜报、活动邀请、展会现场、直播预告 | 中（节日 / 节气高频） | Logo、合影、展位实拍 | card / photo | 低～中（日期、地点、时间） |
| **E. 人才与招商** | 招聘、招商合作 | 低 | Logo、团队照 | list / hero | 高（薪资、电话） |
| **F. 通知与提醒** | 通知公告、调价通知、天气 / 物流提醒、开工大吉、知识科普 | 中（调价、天气随行情 / 季节） | Logo | card / list | 高（日期、涨跌幅） |

几点设计取舍：

- **"现场类"单列为一大类，且版式以照片为主**。钢贸商每天最真实、最有说服力的内容就是"今天发了几车、客户来看货、车间在加工"，这类海报的主角是实拍图，文字只是点题——所以引入 `photo`（全图铺满 + 底部渐变文字）和 `gallery`（1 大 + 2 小拼贴）两种版式，并在规划阶段优先选用带"发货 / 加工 / 接待 / 工程"标签的素材；没有实拍图时自动降级为 hero / list，并提示用户"上传当天实拍效果更好"。
- **促销按触发原因拆开**：特价（日常）、节假日、周年庆、秒杀（限时）、清仓（尾货）、拼单（凑量直发）、开业，文案模板与醒目数字（特价 / 立减 / 秒杀价 / 已拼比例 / 低于市场价）各不相同；识别规则里"节日词 + 促销词 → 节假日促销"、"周年 / 店庆 → 周年庆"优先于普通促销。
- **库存资源表用 `table` 版式**：品名 / 规格 / 钢厂 / 价格四列，由引擎绘制表格而非图像模型生成——这类海报是钢贸商朋友圈最高频的内容之一，且一个数字都不能错。
- **节气日签 / 早安 / 天气提醒**是朋友圈"每日打卡"式的低成本触达，纳入品牌与提醒类，让商家每天都有可发的内容。
- 每个场景还带一个可选的 **角标（tag）**（如"现场直击""NEW""限时""喜报"），由引擎绘制，微调时可一句话去掉。

**共性**：都是"一张图 + 企业信息 + 二维码"，在朋友圈 / 微信群 / 抖音传播；都要带品牌识别（Logo、主色、名称）；一半以上包含**不能错**的数字与联系方式。

### 1.2 用户与使用场景

| 角色 | 端 | 场景 | 关键诉求 |
|------|----|------|---------|
| 老板 / 老板娘（小微商家） | H5 为主 | 节日、开业、招聘，随手发 | 快、好看、不用学、发到微信 |
| 业务员 | H5 | 到货通知、促销，带自己的名片码 | 一分钟出图、自己的联系方式 |
| 运营 / 文员（中型商家） | PC 为主 | 批量、品牌统一、多版本比选 | 素材管理、精细微调、模板沉淀、团队共用 |
| 平台运营 | PC | 为商家代做、审核 | 批量、审核队列 |

### 1.3 核心用户流程

```
选场景(可跳过) → 选/上传素材 → 写一句需求 → [生成中：理解需求→设计版式→生成视觉→排版文案→质检] → 出 1~3 版
   → 看图 → 对话微调（"字大一点""换成红色""电话改成…""换个背景"）→ 版本对比/撤销 → 保存/下载/分享/存为模板
```

- **PC**：三栏工作台——左"素材与品牌"、中"画布与版本"、右"对话与微调"。适合精细工作与批量。
- **H5**：单列分步——需求页 → 生成页 → 结果页（底部对话框微调）。适合随手一张。
- 两端共享同一个"设计 JSON"与渲染引擎，PC 做的模板 H5 可直接用。

## 2. 核心设计决策：为什么不是"一句话直接出整图"

| 方案 | 做法 | 优点 | 致命问题 |
|------|------|------|---------|
| A. 纯文生图 | Prompt → 图像模型直接出含文字的成图 | 最省事、最"AI" | 中文小字错字率 2%~10%；电话 / 价格错一个数字即不可用；不可编辑；每次微调都是重新抽卡（不稳定、慢、贵）；品牌 Logo 无法精确嵌入 |
| B. 纯模板填充 | 固定模板 + 表单填字 | 零错字、可控 | 没有"AI 感"，用户仍要选模板、填表；风格单调；无法理解自然语言 |
| **C. 三层结构（推荐）** | LLM 出"设计 JSON"（版式 / 配色 / 文案 / 用哪张素材）→ 渲染引擎精确排版 → 图像模型生成不含文字的背景 / 视觉元素并合成 | 零错字；可无限微调；风格由模型决定而非固定模板；成本低、速度快；可导出可编辑版本 | 需要自建渲染引擎与版式系统（本仓库行情海报原型已有基础） |
| D. C + 创意模式 | 在 C 之上提供"整图创意模式"：图像模型一步出图作为灵感，再由多模态 LLM 反解为设计 JSON 进入可编辑流程 | 兼得创意与可控 | 二期再做 |

**决策：以 C 为主干，D 作为二期"灵感模式"。** 关键原则：**凡是不能错的信息（企业名、电话、地址、价格、规格、日期、二维码、Logo），永远由渲染引擎绘制，不经过图像模型。**

## 3. 模型选型

### 3.1 需要几类模型

| 环节 | 任务 | 需要的能力 | 类型 |
|------|------|-----------|------|
| ① 需求理解 + 设计规划 | 读用户提示词 + 看素材图 + 品牌信息 → 输出设计 JSON（场景、版式、配色、文案、选哪张图、要不要二维码） | 中文理解、多模态（看图）、结构化输出（JSON Schema）、指令遵循 | 多模态 LLM |
| ② 文案生成 / 改写 | 标题、副标题、要点、祝语、CTA | 中文文案、短句、行业语感 | LLM（可与①同一模型） |
| ③ 视觉生成 | 无文字的背景 / 氛围图 / 装饰元素，按配色与风格 | 中文提示词理解、设计感、可控尺寸、无文字 | 图像生成模型 |
| ④ 视觉编辑 | 局部重绘、扩图、换背景、风格迁移 | 参考图编辑、掩码编辑 | 图像编辑模型 |
| ⑤ 素材处理 | 抠图（Logo / 产品 / 人像）、超分、主色提取 | 专用 | 小模型 / 云 API |
| ⑥ 微调理解 | 把"字大一点 / 换成红色 / 电话改成…"翻译成 JSON diff | 结构化输出、上下文、低延迟、低成本 | 轻量 LLM |
| ⑦ 质检与审核 | 检查溢出 / 对比度 / 敏感词 / 违规图 | 规则 + 内容安全 API + 多模态 LLM 复核 | 混合 |

### 3.2 2026 年可选图像模型对比（③④）

依据公开评测（Atlas Cloud 2026 基准、多家中文实测）整理，数值为参考量级：

| 模型 | 厂商 / 接入 | 中文文字渲染 | 海报设计感 | 局部编辑 | 速度 | 单张成本（参考） | 国内合规 / 可用性 | 评价 |
|------|-----------|------------|-----------|---------|------|----------------|-----------------|------|
| **Seedream 5.0** | 字节 · 火山引擎方舟 | 强（中文实测 ~9.0/10） | **强，最像成稿** | 强（~9.1） | 中 | 低（国内计价） | **合规、稳定、支持备案** | 国内海报首选 |
| **Qwen-Image 2.0** | 阿里 · 百炼 / 开源 | 中上（~7.4） | 强（海报 ~8.6） | **最强（~9.2）** | 中 | 低；可私有化 | 合规；开源可自托管 | 编辑 / 私有化备选 |
| Nano Banana Pro（Gemini 3 Pro Image） | Google | **最强（~9.8）** | 强 | 强 | 快 | 高（$0.06~0.24） | 境外，需出海合规、网络与结算 | 海外版 / 极致文字场景 |
| GPT Image 2 | OpenAI | 强（小字准确率 ~98.5%，中文偶有错字） | 强 | 强 | 中 | 高 | 境外 | 4K 印刷级、UI 复刻 |
| Nano Banana 2 | Google | 中上（~91%） | 中 | 中 | **最快（<1s）** | 极低 | 境外 | 高频草稿 |
| FLUX.2 [pro] / Z-Image Turbo | BFL / 阿里开源 | 一般 | 中 | 中 | 快 | 自托管边际成本极低 | 可私有化 | 批量背景生成、成本敏感 |
| 可图 Kolors / 混元图像 3.0 / 万相 | 快手 / 腾讯 / 阿里 | 中 | 中 | 中 | 中 | 低 | 合规 | 补充备选 |

**结论**：在"三层结构"下，图像模型只负责**无文字的视觉**，因此"文字渲染"权重下降，"设计感 + 编辑能力 + 合规 + 成本"权重上升 → **Seedream 5.0 为主、Qwen-Image 2.0 为辅**是当前最优组合；若二期做"整图创意模式"，Seedream 5.0 的中文文字能力也足以出可用的灵感稿。境外模型放在路由层作为可选后端，不作为国内主链路。

### 3.3 2026 年可选 LLM 对比（①②⑥）

| 模型 | 厂商 / 接入 | 多模态输入 | 结构化输出 | 中文文案 | 价格（¥/百万 tokens，输入 / 输出，参考） | 评价 |
|------|-----------|-----------|-----------|---------|------|------|
| **豆包 Seed 2.0 Pro** | 火山引擎 | 图 / 视频 / 音频 | 支持 | 强 | ~3.2 / 16（≤32K） | 与 Seedream 同一平台，一套账号与计费；指令遵循与视觉理解强 |
| 豆包 Seed 2.0 Lite | 火山引擎 | 全模态 | 支持 | 好 | ~0.6 / 3.6 | 微调环节（⑥）与文案改写的高性价比选择 |
| **通义 Qwen3.5 Plus** | 阿里云百炼 | 图 | 支持 | 强 | ~0.8 / 4.8 | 性价比极高，与 Qwen-Image 同平台；备用主模型 |
| DeepSeek V4 Flash | DeepSeek | 否（基础版） | 兼容 OpenAI 格式 | 强 | ~1 / 2 | 纯文本文案改写最便宜；不能看图 |
| GLM-5 / GLM-5-Turbo | 智谱 | 部分 | 支持 | 强 | ~4~6 / 18~24 | to-B 合规与私有化案例多 |
| Kimi K2.5 | 月之暗面 | 图 / 视频 | 支持 | 强 | ~4 / 21 | 长上下文 Agent，成本偏高 |

**结论**：
- ① 设计规划用 **Seed 2.0 Pro**（需看图、需稍强推理，一次调用 ~2K tokens，成本 ~¥0.03）。
- ② 文案与 ⑥ 微调用 **Seed 2.0 Lite 或 Qwen3.5 Plus**（高频、低延迟、便宜）。
- 备用链路整体切到阿里云（Qwen3.5 Plus + Qwen-Image 2.0），两条链路都在国内、都合规，互为灾备。

### 3.4 推荐组合与路由策略

```
                      ┌─ 主链路（火山引擎）：Seed 2.0 Pro → Seed 2.0 Lite → Seedream 5.0（生成/编辑）
用户请求 → 模型路由层 ─┼─ 备链路（阿里云百炼）：Qwen3.5 Plus → Qwen3.5 Flash → Qwen-Image 2.0（生成/编辑）
                      └─ 可选后端（海外版/高要求）：Nano Banana Pro / GPT Image 2
```

路由规则：
- 默认走主链路；主链路超时 / 限流 / 失败 → 自动切备链路（同一份 prompt 与 JSON Schema，仅换 provider adapter）。
- "局部编辑"类任务优先 Qwen-Image 2.0（编辑评分更高）；"整图氛围"类任务优先 Seedream 5.0。
- 文本微调（⑥）一律走轻量模型；仅当微调涉及视觉才唤起图像模型。
- 所有 provider 通过统一 `ModelGateway` 接口（`plan / copy / refine / genImage / editImage / cutout / moderate`），业务代码不感知厂商，便于按价格与效果随时更换。

### 3.5 为什么不选"只用一个最强多模态模型全包"

Nano Banana Pro / GPT Image 2 一张图就能出很像样的中文海报，但：境外服务在国内 to-B 产品上有合规（生成式 AI 备案要求使用已备案模型）、网络、结算与数据出境问题；单张 $0.06~0.24 是国内模型的 5~10 倍；输出仍是位图，不可编辑、不可精确微调。它们适合作为"海外版"或"灵感模式"的可选后端，不适合做国内主链路。

## 4. 系统架构

```
┌──────────────── 客户端 ────────────────┐
│  PC 工作台 (Web)     H5 (微信内/小程序 WebView) │  共用：设计 JSON、渲染引擎（HTML/Canvas）、对话组件
└───────────────┬────────────────────────┘
                │ HTTPS / SSE（流式返回步骤与结果）
┌───────────────▼────────────────────────┐
│  海报生成服务（BFF）                      │
│  ├ 会话与版本管理（版本树、撤销、分支）      │
│  ├ 生成编排器（Pipeline：理解→规划→视觉→排版→质检）│
│  ├ 微调编排器（指令→JSON diff→按需视觉重绘）  │
│  ├ 模板/版式系统（版式约束、字号/行距/安全区规则）│
│  ├ 渲染服务（无头浏览器/Canvas 出 1080/2160 宽 PNG，服务端与客户端同一渲染代码）│
│  └ 质检（溢出检测、对比度、敏感词、内容安全）   │
├────────────────────────────────────────┤
│  ModelGateway（多厂商适配 / 路由 / 重试 / 计费 / 缓存 / 观测）│
│   Seed 2.0 Pro/Lite · Seedream 5.0 │ Qwen3.5 · Qwen-Image 2.0 │ 抠图 · 超分 · 内容安全 │
├────────────────────────────────────────┤
│  素材服务：上传 → 去重 → 抠图 → 主色提取 → 打标（多模态 LLM）→ 品牌 Kit │
│  存储：OSS（素材、成图）· MySQL（会话、版本、模板）· Redis（任务队列、缓存）│
└────────────────────────────────────────┘
```

关键点：
- **同一套渲染代码前后端共用**（浏览器预览 = 服务端出图），避免"预览和下载不一样"。
- **流式过程**（SSE）把"理解需求 → 设计版式 → 生成视觉 → 排版文案 → 质检"逐步推给前端，用户看得到进度，等待 5~10s 也不焦虑。
- **视觉生成异步 + 先出框架**：LLM 规划完成后立即用纯色 / 渐变背景渲染出"预览稿"，图像模型出图后再替换背景，首屏 <3s。

## 5. 生成流水线（Pipeline）

### 5.1 步骤

| 步骤 | 输入 | 调用 | 输出 | 耗时目标 |
|------|------|------|------|---------|
| 1 理解需求 | 提示词、场景（可选）、素材缩略图、品牌 Kit、最近 3 张历史海报（风格延续） | Seed 2.0 Pro（多模态，JSON Schema） | `DesignSpec`（见 5.3） | 2~4s |
| 2 文案补全 | DesignSpec 中未填满的文案槽 | Seed 2.0 Lite | 标题 / 副标题 / 要点 / CTA / 祝语，各给 2 个备选 | 1~2s（与 3 并行） |
| 3 视觉生成 | DesignSpec.visual（风格、配色、构图、尺寸、"无文字"约束）+ 可选参考图（用户素材） | Seedream 5.0 | 1~2 张无文字背景 / 主视觉 | 3~8s（异步） |
| 4 排版渲染 | DesignSpec + 素材 + 背景 | 渲染引擎（客户端即时 / 服务端出图） | 预览 & 1080 宽 PNG | <0.5s |
| 5 质检 | 渲染结果 | 规则（溢出、对比度、安全区、二维码尺寸 ≥ 180px）+ 内容安全 API + 可选多模态复核 | 通过 / 自动修正（缩字号、换配色）/ 打回重规划 | <1s |

### 5.2 系统提示词（规划环节，节选）

```
你是一名服务钢材贸易企业的资深平面设计师与文案。根据用户需求、企业信息与素材，输出一份 DesignSpec JSON（严格符合给定 Schema）。
规则：
1. 精确信息（企业名、电话、地址、价格、规格、日期）只能来自用户输入或品牌资料，禁止编造；没有就留空并在 notes 说明。
2. 文案短、有力、口语化，标题 ≤ 12 字，副标题 ≤ 20 字，要点每条 ≤ 14 字，最多 5 条。
3. 版式从 [hero, split, list, card, photo, gallery, table] 中选；现场实拍类（发货 / 加工 / 接待 / 工程 / 展会）优先 photo 或 gallery（≥2 张图）；有产品 / 门头照片优先 split；招聘 / 目录 / 加工服务优先 list；库存报价类用 table；节日 / 通知 / 邀请优先 card。没有可用照片时不得选 photo / gallery / split。
4. 配色从品牌主色出发，节日/喜庆可用红金，工业可用深灰橙，商务可用深蓝，除非用户明确要求。
5. 视觉 prompt 用于图像模型，必须描述"无任何文字、无 Logo、无人脸"的背景或氛围图，注明构图留白位置（供文字排版）。
6. 若素材中有 Logo，showLogo=true；有二维码需求或用户是销售员，showQR=true。
```

### 5.4 版式系统（渲染引擎约束）

- 7 种版式 × 3 种画幅（3:4 朋友圈、9:16 竖屏、1:1 方图）：`hero` 主视觉大字、`split` 上图下文、`list` 标题 + 要点卡、`card` 居中卡片、`photo` 全图实拍（照片铺满 + 上下渐变压暗 + 底部文字）、`gallery` 多图拼贴（1 大 + 2 小，支持 2~3 张实拍）、`table` 表格清单（品名 / 规格 / 钢厂 / 价格）。每种定义安全区、字号区间、元素优先级（内容多时按 "装饰 → 副标题 → 要点条数" 顺序降级，与行情海报原型的自适应逻辑一致）。
- 文本自动换行优先在标点 / 空格处断行；标题自动字号（fitSize）；要点超 5 条自动截断并提示。
- 精确元素（Logo、二维码、电话）固定层级最高，永不被背景遮挡；二维码最小 180px（1080 宽画布）。
- 输出：PNG（1080 / 2160 宽）、可编辑 JSON、（二期）PSD / SVG。

## 6. 微调机制（对话式修改）

### 6.1 原理

```
用户："字大一点，换成红色喜庆一点，电话改成 139 1234 5678，去掉地址"
   ↓ Seed 2.0 Lite（输入：当前 DesignSpec + 指令 + 允许的操作集，输出 JSON Patch）
[
  { "op": "replace", "path": "/fontScale", "value": 1.15 },
  { "op": "replace", "path": "/style", "value": "festive" },
  { "op": "replace", "path": "/palette", "value": { "...红金配色" } },
  { "op": "replace", "path": "/contact/phone", "value": "139 1234 5678" },
  { "op": "replace", "path": "/flags/showAddr", "value": false },
  { "op": "regen_visual", "reason": "风格由 business 变为 festive，需要重绘背景" }
]
   ↓ 引擎应用 patch 并即时重渲染（<0.5s）；若含 regen_visual 则异步调用 Seedream 局部/整体重绘并替换
   ↓ 回复用户："已放大字号 15%、换为红金喜庆配色并重绘背景、更新电话、隐藏地址。要不要把标题也改得更喜庆？"
```

### 6.2 指令类型与处理方式

| 指令类型 | 示例 | 处理 | 是否调用图像模型 |
|---------|------|------|----------------|
| 文本修改 | 标题改为「…」/ 把 A 改成 B / 电话改成… | patch copy / contact | 否 |
| 排版参数 | 字大一点 / 更简洁 / 更丰富 / 换个版式 / 居中 / 全图铺满 / 多图拼贴 / 用第二张图 | patch fontScale / density / layout / assets.photos | 否 |
| 配色风格 | 红色 / 黑金 / 更商务 / 更喜庆 | patch palette / style；风格变化大时 regen_visual | 视情况 |
| 元素开关 | 加二维码 / 去掉地址 / 不要 Logo | patch flags | 否 |
| 画幅 | 改成竖屏 / 方图 / 朋友圈 | patch ratio（背景需扩图） | 扩图 |
| 素材 | 用第二张图 / 换成刚上传的照片 | patch assets.photo | 否（可能需抠图） |
| 视觉 | 换个背景 / 背景更亮 / 加点金色粒子 | 修改 visual.prompt → regen_visual 或局部编辑 | 是 |
| 版本 | 撤销 / 回到第 2 版 / 保留这版再来一版 | 版本树操作，不调模型 | 否 |
| 模糊 | 再好看一点 / 高级一点 | 模型自行组合 2~3 个安全操作并解释 | 视情况 |

### 6.3 版本与可控性

- **版本树**：每次生成 / 微调生成新版本节点，可回退、可从任一版本分支；PC 端显示版本条，H5 端左右滑动切换。
- **元素锁定**：用户可锁定标题 / 电话 / 配色，锁定项在后续微调中不被模型修改（作为约束传入）。
- **解释与建议**：每次微调回复"改了什么 + 一个下一步建议"，降低用户表达成本。
- **快捷微调**：常用指令做成 chips（更喜庆 / 更商务 / 字大一点 / 换背景 / 加二维码 / 换成竖屏），点击即发。

### 6.4 海报历史记录

商家做海报是"每天一两张、常常翻旧账"的高频行为：昨天的库存表改个价再发、上周的发货实拍换张图、去年的国庆促销拿来改成今年的。历史记录不是一个"列表页"，而是**把每次生成都自动变成可复用资产**。

**记录粒度**：一条记录 = 一次海报会话（`poster_session`），包含首次生成到所有微调的版本链（`poster_version[]`）、原始需求提示词、场景 / 风格 / 版式 / 画幅、生成端（PC / H5）、使用情况（导出次数、分享次数）、收藏标记。生成即自动保存，无需用户点"保存"。

| 能力 | PC 工作台 | H5 |
|------|-----------|-----|
| 入口 | 顶栏「历史记录」（带数量角标）打开右侧抽屉；对话欢迎区显示最近 3 张"继续改" | 首页顶部横向「最近做的海报」条 + 右上「历史」；独立历史页 |
| 浏览 | 按"今天 / 昨天 / 本周 / 本月 / 更早"分组的卡片网格；卡片 = 实时渲染缩略图 + 标题 + 场景 + 端 + 画幅 / 风格 + 时间 + 版本数 + 使用状态 | 同样按日分组的双列卡片；顶部统计（全部 / 近 7 天 / 导出分享 / 收藏） |
| 筛选 | 左栏按 6 大类 → 场景两级筛选；时间范围；状态（草稿 / 已导出分享）；排序（最近修改 / 创建时间 / 使用最多 / 版本最多）；只看收藏；全文搜索（标题 / 需求 / 文案 / 场景） | 分类页签 + 收藏页签；时间范围；搜索 |
| 操作 | 打开继续改（载入完整版本链，回到工作台，继续微调保存到同一条记录）· 再做类似（带入原需求与场景，新建会话）· 导出 · 收藏置顶 · 删除 | 点卡片打开；「⋯」弹出操作面板：打开 / 再做类似 / 保存原图 / 收藏 / 删除 |
| 状态回写 | 导出、分享时自动记为"已导出 / 已分享 N 次"，用于排序"使用最多"与首页推荐 | 同 |
| 多端 | PC / H5 共用同一份记录（按 merchant_id + user_id），手机上发的实拍海报可以回到 PC 上精修 | 同 |

**与"版本"的关系**：版本条 / 左右滑动解决的是"这一张的第几稿"，历史记录解决的是"我做过哪些张"。打开历史记录会恢复整条版本链，可以从任一旧版本继续分支。

**与"模板"的关系**：历史是自动的、私有的、按时间流动的；模板是手动沉淀的、可共享给团队的、按用途组织的。历史卡片上提供"存为模板"，是从历史到模板的通道。

**正式版补充**：删除进入回收站（30 天）；同一会话超过 50 个版本时折叠中间版本只保留关键节点；列表按 `updated_at` 分页；缩略图由服务端渲染 `thumb_url`（原型为前端实时渲染）；支持团队视图（管理员看全员海报、按人筛选）与"素材被哪些海报使用过"反查。

### 8.3 ModelGateway 接口

```ts
interface ModelGateway {
  plan(input: { prompt; scene?; brand; assets: AssetBrief[]; history?: Spec[] }): Promise<Spec>;
  copy(input: { spec; slots: string[] }): Promise<Partial<Copy>>;
  refine(input: { spec; instruction; locks?: string[] }): Promise<{ patch: JsonPatch[]; reply: string; regenVisual?: boolean }>;
  genImage(input: { prompt; size; refs?: string[]; seed? }): Promise<{ url; seed }>;
  editImage(input: { image; mask?; prompt; mode: 'inpaint'|'outpaint'|'restyle' }): Promise<{ url }>;
  cutout(image: string): Promise<{ url }>;
  moderate(input: { text?: string; image?: string }): Promise<{ pass: boolean; reasons?: string[] }>;
}
```

每个 provider 实现同一接口；网关负责路由、重试、超时、成本记录（每次调用记 provider / tokens / 张数 / 费用）与结果缓存（相同 spec.visual.prompt + seed 直接复用背景图）。

## 10. 质检、合规与风控

- **生成式 AI 合规**：使用已完成备案的国内模型（火山引擎 / 阿里云均提供备案模型清单）；产品自身按《生成式人工智能服务管理暂行办法》做算法备案评估；生成图片添加显式 / 隐式标识（按《人工智能生成合成内容标识办法》）。
- **内容安全**：提示词、生成文案、生成图片三处过内容安全 API；敏感行业词（如"最低价""第一"等广告法禁用语）用规则库拦截并给出替代文案。
- **版权**：仅用可商用字体；用户素材需确认授权；图像模型输出不含真实品牌 Logo / 名人。
- **数据**：素材与成图按商家隔离；不用于模型训练（合同约定）；境外模型（如启用）不传企业敏感信息。
- **质量兜底**：溢出 / 对比度不达标自动修正；连续失败给保底模板；每次调用记录 model_trace 便于回溯。

| **一次完整生成** | **~¥0.25~0.45** | 出 1 版；3 版约 ¥0.6~0.9（视觉可共用） |

性能目标：首个可视预览 ≤3s（LLM 规划 + 纯色背景即时渲染），完整成图 ≤10s，文本微调 ≤2s，导出 ≤3s。

## 13. 指标

- 生成成功率（质检通过 / 请求）≥ 95%；首屏预览 P90 ≤ 3s；完整成图 P90 ≤ 10s。
- 一次满意率（不微调直接下载）≥ 40%；平均微调次数 ≤ 3；微调后下载率 ≥ 70%。
- 单张成本 ≤ ¥0.5；模型故障切换成功率 100%。
- 商家周活（至少生成 1 张）、人均月生成张数、分享 / 扫码回流（与追踪码体系打通）。

## 14. 风险与对策

| 风险 | 对策 |
|------|------|
| 模型输出 JSON 不合规 / 编造电话价格 | JSON Schema 严格校验 + 精确字段只允许来自输入（后置校验：电话 / 价格必须在用户输入或品牌 Kit 中出现）|
| 图像模型出图带文字 / 水印 / 人脸 | prompt 强约束 + 负向词 + 多模态复核，不合格自动重抽（≤2 次）后降级为程序化背景 |
| 风格千篇一律 | 版式 × 配色 × 背景动效组合库持续扩充；规划 prompt 注入"最近 3 张海报风格"要求差异化 |
| 厂商价格 / 能力变化 | ModelGateway 抽象，按月评估切换；关键 prompt 与 Schema 与厂商无关 |
| 用户不会写提示词 | 场景 chips + 示例提示词 + "只填电话和一句话也能出图"；H5 支持语音 |
| 合规 | 只用备案模型、三处内容安全、生成标识、广告法词库 |

## 附：原型说明

`prototypes/ai-poster/` 下为高保真可交互原型（纯前端，无需服务端；"大模型"由规则模拟，用于演示交互与版式效果）：

- `pc.html` — PC 三栏工作台：素材库与品牌 Kit（可真实上传图片）、画布 / 画幅切换 / 版本条、对话式生成与微调（支持"字大一点 / 换成红色 / 电话改成… / 去掉地址 / 换背景 / 换成竖屏 / 标题改为…"等指令）、生成过程步骤、导出原图。
- `h5.html` — 手机端分步流程：需求 → 生成 → 结果与底部对话微调、版本左右切换、保存 / 分享。
- `poster.html` — 1080 宽原图渲染页（`?d=<base64 设计 JSON>`），演示"前后端同一渲染代码"。
- `shared/engine.js` — 场景库、配色 / 风格库、模拟规划与微调、渲染引擎。正式实现时，`mockPlan / mockRefine` 替换为 ModelGateway 调用，渲染引擎可直接复用。
