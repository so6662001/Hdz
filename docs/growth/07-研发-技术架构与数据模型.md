# 研发方案 · 技术架构与数据模型

> 给技术团队的落地蓝图：模块划分、核心数据模型、关键 API、事件流。表结构为概念模型（字段为示意），具体类型/索引由实现时确定。

---

## 1. 模块总览（建议微服务/模块边界）

```
┌──────────────────────────────────────────────────────────────┐
│                         接入层 / BFF                            │
│   小程序 / H5 / App / 商家工作台 / 运营后台                      │
└──────────────────────────────────────────────────────────────┘
        │            │             │            │           │
┌───────────┐ ┌────────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ 行情服务   │ │ 资源/交易   │ │ 拼单服务  │ │ 活动/任务 │ │ 海报生成 │
│ Quote     │ │ Resource/   │ │ GroupBuy │ │ Campaign/ │ │ Poster   │
│           │ │ Trade       │ │          │ │ Task      │ │          │
└───────────┘ └────────────┘ └──────────┘ └──────────┘ └──────────┘
        │            │             │            │           │
        └────────────┴──────┬──────┴────────────┴───────────┘
                            │ 行为事件 (MQ)
        ┌───────────────────┴───────────────────────┐
        │              底层引擎层                      │
   ┌──────────────┐  ┌──────────────────┐  ┌──────────────┐
   │ 追踪归因引擎  │  │   激励/积分引擎    │  │  风控引擎     │
   │ Attribution  │  │   Incentive       │  │  RiskControl │
   │ + 线索 Lead  │  │                   │  │              │
   └──────────────┘  └──────────────────┘  └──────────────┘
        │
   ┌──────────────────────────────────────────────┐
   │  基础服务: 用户/企业认证, 短链/二维码, 支付/担保, │
   │  消息推送(企微/公众号/短信), 数据看板/BI          │
   └──────────────────────────────────────────────┘
```

**核心设计思想：事件驱动。** 各玩法只负责自己的业务，并把"行为事件"投递到消息队列；归因、激励、风控作为消费者统一处理。这样玩法与引擎解耦，新增玩法不影响引擎。

## 2. 关键行为事件（统一事件总线）

所有玩法上报标准事件，引擎消费：

| 事件 | 触发时机 | 主要消费者 |
|------|---------|-----------|
| `CONTENT_SHARED` | 用户分享任意素材 | 归因(建分享记录)、激励(分享奖励)、风控 |
| `LINK_CLICKED` | 追踪链接被点击 | 归因、风控 |
| `USER_REGISTERED` | 新用户注册/认证 | 归因(绑定referrer)、激励(邀请奖) |
| `LEAD_SUBMITTED` | 用户留资 | 线索、归因、激励 |
| `ORDER_CREATED` | 下单/参与拼单 | 拼单、归因、风控 |
| `DEAL_CONFIRMED` | 成交/回款确认 | 激励(发佣金)、归因、看板 |
| `TASK_ACTION` | 完成某任务动作 | 任务、激励 |

事件公共字段：`event_id`(幂等), `user_id`, `spread_code?`, `occurred_at`, `payload`。

## 3. 核心数据模型（概念表）

### 3.1 用户与企业
```
user(id, phone, nickname, avatar, role[buyer/seller/both], 
     referrer_user_id,        -- 首次归因绑定的上级
     referrer_bound_at, growth_level, status, created_at)

enterprise(id, owner_user_id, name, credit_code, 
           verify_status, business_type[mill/trader/factory/...], region)
```

### 3.2 追踪与归因
```
spread_content(id, type[quote_poster/resource/groupbuy/invite/campaign], 
               ref_id,           -- 指向具体行情/资源/拼单/活动
               owner_user_id, created_at)

spread_record(id, spread_code UNIQUE, content_id, spreader_user_id, 
              channel, created_at, expire_at)        -- 一次分享=一条

touch_event(id, spread_code, visitor_user_id?, anon_id?, 
            type[view/click/register/lead/order/deal], 
            ref_order_id?, occurred_at, ip, device_fp)

attribution(id, target_type[user/lead/order], target_id, 
            spreader_user_id, parent_spreader_user_id?,  -- 二级
            rule[first_touch/last_touch], created_at)
```

### 3.3 线索
```
lead(id, source_spread_code?, owner_user_id,       -- 归属商家/帮卖人
     contact_name, contact_phone(脱敏存储), enterprise_name,
     demand(品名/规格/材质/数量/目标价/交期), 
     score, status[new/assigned/following/quoted/won/lost], 
     created_at, updated_at)
```

### 3.4 行情
```
quote(id, category[螺纹/线材/热卷/冷卷/...], spec, region, 
      price, change, change_pct, quote_date, source, level[free/unlock/vip])

quote_poster_template(id, name, style, layout_schema)

quote_subscription(id, user_id, categories[], regions[], channel, status)

quote_guess(id, user_id, category, guess[up/down], guess_date, 
            result, reward_status)
```

### 3.5 资源与帮卖分销
```
resource(id, seller_user_id, title, category, spec, material, origin, 
         quantity, unit, price, warehouse, 
         commission_type[fixed/percent], commission_value, 
         audit_status, status[on/off/sold], created_at)

resell_relation(id, resource_id, reseller_user_id, spread_code, created_at) -- 帮卖关系

distribution_relation(id, user_id, parent_user_id, level<=2, created_at)    -- 分销层级(二级封顶)

purchase_request(id, buyer_user_id, demand(品名/规格/量/目标价/交期), 
                 bounty_amount?, status, created_at)                        -- 求购/悬赏
```

### 3.6 拼单
```
groupbuy(id, initiator_user_id[团长], seller_user_id, resource_id?, 
         type[volume/ladder/carpool/presale], 
         target_qty, current_qty, 
         ladder_rules[{min_qty, price}...],        -- 阶梯价
         start_at, end_at, lock_price_policy, 
         status[ongoing/success/failed/fulfilling/done])

groupbuy_order(id, groupbuy_id, buyer_user_id, qty, 
               deposit, total, spread_code?, 
               status[joined/paid/refunded/fulfilled], created_at)
```

### 3.7 激励
```
incentive_account(id, user_id, 
                  points_balance, cash_balance, 
                  commission_frozen, commission_available, 
                  growth_value)

ledger_entry(id, user_id, currency[points/cash/commission/growth], 
             amount(+/-), biz_type, biz_ref_id, idempotency_key UNIQUE, 
             balance_after, created_at)   -- 不可变流水

reward_rule(id, trigger_event, currency, calc_type[fixed/percent/ladder], 
            calc_config, limits(daily_cap/total_cap/new_user_only), 
            grant_mode[instant/delayed/review], budget, period, status)

withdraw(id, user_id, currency, amount, status, channel, 
         tax_info, created_at)
```

### 3.8 活动与任务
```
task(id, code, name, type[daily/newbie/viral/growth/limited], 
     condition_event, target_count, reward_rule_id, period, status)

task_progress(id, user_id, task_id, progress, completed_at, claimed)

campaign(id, type[invite/lottery/discount/festival], config, 
         start_at, end_at, budget, status)

invite_record(id, inviter_user_id, invitee_user_id, spread_code, 
              activated(bool), reward_status, created_at)

leaderboard(id, type, period, metric)         -- 榜单定义
leaderboard_entry(board_id, user_id, score, rank, period)
```

### 3.9 风控
```
risk_event(id, user_id, type[multi_account/self_deal/click_fraud/...], 
           score, evidence, action[none/freeze/review/blacklist], created_at)

device_fingerprint(id, fp_hash, user_ids[], ip_set[], first_seen, last_seen)
```

## 4. 关键 API（示意，REST 风格）

### 分享与归因
```
POST /api/spread                 # 生成分享素材+spread_code, 返回短链/二维码/海报url
GET  /s/{spread_code}            # 落地页, 记录点击/归因cookie
POST /api/touch                  # 上报触点事件(view/lead/...)
GET  /api/me/attribution/stats   # 我带来的访问/线索/成交/佣金
```

### 行情
```
GET  /api/quotes?category=&region=&level=     # 行情列表(按等级过滤)
POST /api/quotes/{id}/poster                  # 生成我的专属行情海报
POST /api/quotes/unlock                        # 邀请/积分解锁高级行情
POST /api/quote-guess                          # 竞猜
```

### 资源与帮卖
```
POST /api/resources                            # 商家发布资源(含佣金规则)
POST /api/resources/{id}/resell                # 我要帮卖, 生成专属码
GET  /api/me/resell/earnings                   # 我的帮卖收益
POST /api/purchase-requests                    # 发布求购/悬赏
```

### 拼单
```
POST /api/groupbuys                            # 发起拼单
POST /api/groupbuys/{id}/join                  # 参与拼单(下单/付定金)
GET  /api/groupbuys/{id}                       # 进度/当前档位/差额
```

### 激励
```
GET  /api/me/incentive                          # 我的积分/现金/佣金/等级
POST /api/me/withdraw                           # 提现
GET  /api/me/ledger                             # 流水
POST /api/me/tasks/{id}/claim                   # 领取任务奖励
```

### 线索（商家端）
```
GET  /api/seller/leads?status=                  # 我的线索
PATCH /api/seller/leads/{id}                    # 更新跟进状态
```

## 5. 技术选型建议（参考，按团队栈调整）

- 后端：Java(Spring Cloud) / Go / Node 均可，强调"事件驱动 + 服务解耦"。
- 消息队列：Kafka / RocketMQ（事件总线、削峰、解耦）。
- 存储：MySQL/PostgreSQL（业务+流水），Redis（计数器、排行榜 ZSET、库存、防并发锁），ClickHouse/数仓（埋点分析、看板）。
- 海报生成：服务端渲染（无头浏览器/图片库）+ 模板 + CDN 缓存。
- 短链/二维码：自建短链服务 + 微信小程序码/二维码 API。
- 触达：微信公众号/企业微信/小程序订阅消息/短信。
- 风控：规则引擎 + 设备指纹 + 关系图谱（图数据库可选）。

## 6. 非功能要求

- **幂等**：发奖、扣减、归因、支付全链路幂等键。
- **一致性**：拼单库存/累计量、积分账户用乐观锁/分布式锁；资金走可靠消息+对账。
- **可观测**：埋点、日志、链路追踪、奖池/积分发行监控告警。
- **合规与安全**：个人信息脱敏与最小授权；分销合规；资金/税务合规；防爬虫。
- **可配置**：奖励规则、任务、活动、归因规则尽量后台配置化，减少发版。
