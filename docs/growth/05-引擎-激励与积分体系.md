# 底层引擎一 · 激励与积分体系

> 所有玩法的"发奖"都汇聚到这里。它是一个统一的、可配置的"奖励发放与核销中台"，避免每个玩法各搞一套钱包，导致账目混乱、风控失效。

---

## 1. 设计原则

1. **统一账户、统一流水**：积分、红包、佣金、成长值都走同一套账户与流水体系，所有进出可追溯、可对账。
2. **规则配置化**：奖励规则（什么行为、奖多少、上限、有效期）由运营在后台配置，少改代码。
3. **奖励真实行为，不奖励虚假动作**：尽量挂钩"带来真实新用户 / 真实成交"，而非"点击/转发次数"。
4. **可控成本**：抽奖优先于直接发现金；设预算与上限；高价值奖励延迟+审核发放。
5. **强幂等、防并发**：发奖/扣减必须幂等，防止重复发、超发。

---

## 2. 四种激励货币

| 货币 | 性质 | 来源 | 用途 | 风险 |
|------|------|------|------|------|
| **积分 Points** | 可消耗、可获取 | 任务、签到、互动、行为 | 兑权益/抵扣/抽奖/解锁 | 通胀，需控发放与消耗平衡 |
| **红包/现金 Cash** | 可提现资金 | 邀请奖、活动奖 | 提现 | 薅羊毛、资金合规 |
| **佣金 Commission** | 交易分成资金 | 帮卖/分销/团长成交 | 提现/转积分 | 刷单、税务合规 |
| **成长值 Growth** | 不可消耗 | 行为累积 | 决定等级/特权 | 防刷榜 |

> 建议：日常激励主用**积分**（成本可控）；拉新关键动作用少量**现金红包**点火；交易相关用**佣金**（按成交付费，本身健康）。

---

## 3. 账户与流水模型（概念）

- **激励账户 IncentiveAccount**：每个用户每种货币一个余额（积分余额、现金余额、佣金账户冻结/可提现、成长值）。
- **流水 LedgerEntry**：每一笔进出都有一条不可变流水（谁、哪种货币、+/-、金额、来源业务、关联单据、时间、幂等键）。
- **佣金三态**：`冻结(成交待确认)` → `可提现(确认/回款后)` → `已提现`。
- 对账：定时对账任务，保证 Σ流水 = 余额，发现异常告警。

详见 [`07-研发-技术架构与数据模型.md`](./07-研发-技术架构与数据模型.md) 的表结构。

## 4. 奖励规则引擎

把"行为 → 奖励"抽象成可配置规则：

```
规则 = {
  触发事件: "SHARE_QUOTE_POSTER" / "INVITE_ACTIVATED" / "DEAL_CONFIRMED" / ...
  奖励货币: 积分 / 现金 / 佣金 / 成长值
  奖励计算: 固定值 | 比例(基于成交额) | 阶梯
  限制: 每日上限 / 每人总上限 / 活动周期 / 仅新用户 / 需有效行为
  发放方式: 即时 | 延迟 | 需审核
  预算: 活动总预算上限(撞顶停发)
}
```

- 玩法只需"上报行为事件"，由规则引擎决定发不发、发多少 → 玩法与激励解耦。
- 运营可随时调参（如大促期间"邀请奖励翻倍"），无需发版。

---

## 5. 积分经济（防通胀）

积分玩法最容易死于"通胀"——发得多、用得少，积分贬值，激励失效。

- **建立消耗出口**：行情解锁、抽奖、兑实物、抵扣服务费、兑会员、专属资源位竞拍。
- **发放-消耗动态平衡**：监控积分发行量 vs 消耗量，调节发放系数。
- **有效期/衰减**：积分设有效期或定期清零部分，促使尽快消耗。
- **积分商城**：稳定的兑换出口（话费/油卡/钢贸耗材/平台权益/抽奖），让积分"值钱"。

---

## 6. 风控（激励侧）

- **幂等与上限**：每个奖励规则强制日上限、总上限；发奖幂等键防重发。
- **新用户有效性**：邀请/解锁类奖励，要求被带用户完成"实名/企业认证 + 有效行为"才计奖。
- **设备/关系图谱**：识别同设备、同 IP、同收款账户、相互邀请的"羊毛团伙"。
- **延迟发放 + 审核**：大额奖励先冻结、风控审核后再放。
- **黑灰名单**：命中风险的账户冻结奖励、限制提现。
- **预算熔断**：活动奖池见底自动停发，防止被刷穿。

---

## 7. 研发要点

- 高并发下账户增减用乐观锁/分布式锁 + 幂等键，保证不超发不重发。
- 流水不可变、只追加，便于审计与对账。
- 事件驱动：玩法发"行为事件"到消息队列，激励引擎消费并按规则发奖，削峰解耦。
- 与提现/支付/税务系统对接（现金、佣金提现）。
