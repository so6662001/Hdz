# 底层引擎二 · 分享追踪与线索归因

> **这是整套裂变系统的地基，建议最先开发。** 没有它：分不清谁带来的客户、线索归谁、佣金算谁，商家就没有动力转发，所有玩法都成了空中楼阁。
> 它要回答三个问题：**谁分享的？谁带来的？这条线索/这单算谁的？**

---

## 1. 核心概念

- **传播者 Spreader**：发起分享的人（商家/帮卖人/团长/任意用户）。
- **传播素材 Spread Content**：被分享的东西（行情海报、资源卡片、拼单、邀请、活动）。
- **传播码 Spread Code / 追踪码**：每次"分享"生成的唯一标识，编码了"谁 + 分享了什么 + 通过什么渠道 + 哪一次"。
- **渠道 Channel**：朋友圈 / 微信群 / 单聊 / 公众号 / 短信 / 线下二维码……
- **触点事件 Touch Event**：被分享对象产生的行为（点击、浏览、留资、注册、下单、成交）。
- **归因 Attribution**：把"触点/线索/成交"关联回某个传播者（及上级），用于发奖与线索分配。

---

## 2. 一次分享的全链路

```
[传播者] 在某素材上点"分享"
   → 系统生成 spread_code（含 spreader_id, content_id, channel, ts, nonce）
   → 生成带 spread_code 的 短链 / 小程序码 / 二维码 / 海报
   → 传播者发到 朋友圈/社群/单聊
   → [新用户] 点击 → 落地页带 spread_code
      → 浏览(Touch: VIEW)
      → 留资/注册(Touch: LEAD / REGISTER)  → 绑定归因关系: user.referrer = spreader
      → 下单/成交(Touch: ORDER / DEAL)     → 成交归因 → 触发佣金/积分(接激励引擎)
   → 全过程事件写入 追踪流水，可回溯
```

---

## 3. 归因模型（重点，决定钱怎么分、客户算谁）

钢贸决策链长、多次触达，归因必须想清楚，否则纠纷不断。

### 3.1 归因窗口
- 设置归因有效期（如点击后 7/15/30 天内留资/成交才归因），过期不算。

### 3.2 归因优先级（建议规则，可配置）
1. **首次绑定优先（推荐用于"用户归属/线索归属"）**：新用户首次通过谁的码进来注册，长期归属于谁（类似"谁的客户"）。适合帮卖分销的"我的客户池"。
2. **末次触点优先（可用于"单笔成交佣金"）**：某笔成交前最后一次有效分享算谁的，鼓励临门一脚。
3. **混合**：用户归属用首次，单笔成交佣金用末次（或按规则在多个传播者间分配）。

> 建议：**用户级归属=首次绑定**（一个买家长期算某个商家/帮卖人的客户）；**订单级佣金=按该订单实际来源传播者**。两套口径分开，避免"客户是我的但单算别人"的扯皮——具体规则配置化，便于调整。

### 3.3 多级归因
- 帮卖二级分销时，记录直推人和间推人，佣金按规则分配（二级封顶，合规）。

### 3.4 冲突与去重
- 同一新用户被多人分享：按归因优先级裁决，结果对所有相关方透明可查。
- 自己点自己的码、关联账户互点：风控过滤，不计归因/不发奖。

## 4. 线索（Lead）管理

裂变的最终交付物之一就是**线索**，要管好。

- **线索定义**：留资（电话/企业/采购意向/品名规格量）即生成一条线索。
- **线索归属**：按归因规则分配给对应商家/帮卖人；平台公海线索按规则派发。
- **线索状态**：新建 → 已分配 → 跟进中 → 已报价 → 已成交 / 已关闭（无效/战败）。
- **线索评分**：按企业资质、采购量、行为活跃度打分，优先派发高质量线索。
- **隐私与脱敏**：联系方式按权限展示，防爬取、防倒卖；符合个人信息保护要求。
- **承接**：线索可推送到商家端 / 企业微信 / SCRM，及时跟进，避免浪费。

> 这直接回应你的核心诉求"获客（线索）"：裂变带来的所有留资，都通过这套归因规则，准确、透明地变成商家可跟进的线索。

---

## 5. 数据埋点与统计

- 全链路埋点：曝光、点击、浏览时长、留资、注册、下单、成交。
- 传播者维度看板：我分享了多少、带来多少访问/线索/成交/佣金（商家最关心这个）。
- 内容维度看板：哪条行情/资源/拼单传播最广、转化最高 → 指导选题与货品运营。
- 渠道维度：朋友圈 vs 社群 vs 单聊 哪个渠道效率高。
- 平台全局：K 因子、裂变层级深度、获客成本(CAC)、各玩法贡献度。

---

## 6. 风控（归因侧）

- **防刷点击/假留资**：人机识别、频率限制、无效号码/重复留资过滤。
- **防自我归因/关联归因**：设备指纹、关系图谱识别自买自卖、互助刷单。
- **防恶意抢归因**：归因规则透明、可申诉、有日志可回溯。
- 所有归因结果可追溯、可复算，争议时有据可依。

---

## 7. 研发要点

- **短链/小程序码服务**：高并发生成与解析，spread_code 编码紧凑、不可猜。
- **事件采集管道**：埋点事件 → 消息队列 → 实时处理 + 落库（行为流水）。
- **归因服务**：按可配置规则计算归因，输出"用户归属""订单佣金归属""线索归属"。
- **线索服务**：线索 CRUD、分配、状态机、评分、脱敏、推送对接。
- 与激励引擎（`05`）通过"成交确认事件"联动发佣金；与各玩法通过"分享/触点事件"联动。
- 数据模型与 API 见 [`07-研发-技术架构与数据模型.md`](./07-研发-技术架构与数据模型.md)。

---

## 8. 为什么先做它

行情海报要带追踪码才知道谁带的客；帮卖要归因才能发佣金；拼单团长要归因才能算团长功劳；邀请有礼要归因才能发奖。**所有玩法都依赖它。先把这块地基打牢，后面每个玩法都是"接上来就能跑"。**
