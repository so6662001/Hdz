# 货袋子平台 — 微信小程序设计方案

> 版本：v1.0 | 日期：2026-02-23

---

## 一、为什么要做小程序

### 1.1 PC 端 vs 小程序端的定位差异

| 维度 | PC 端（已确认） | 微信小程序 |
|------|----------------|-----------|
| 核心用户 | 运营人员（后台）、企业主（浏览） | 普通用户（高频浏览）、企业主（快速登记） |
| 使用场景 | 办公桌前、深度浏览 | 移动碎片化、随时随地 |
| 流量入口 | 搜索引擎、直接访问 | 微信搜索、朋友圈分享、微信群转发、公众号引流、扫码 |
| 核心价值 | 完整管理、数据分析 | 快速触达用户、社交裂变、降低使用门槛 |
| 登录方式 | 账号密码 | 微信一键授权（零门槛） |
| 定位方式 | IP 定位 | 微信定位 API（GPS 级精准） |

### 1.2 小程序的核心优势

1. **免安装、即用即走**：用户无需下载，微信内直达，转化路径最短
2. **微信社交裂变**：广告页面可一键分享到微信群/朋友圈，带来免费流量
3. **精准定位**：微信 `wx.getLocation` 精准到街道级别，远超 IP 定位
4. **微信登录**：一键授权获取用户身份，零注册门槛
5. **订阅消息**：可向用户推送招商/广告相关通知（替代短信，免费）
6. **扫码能力**：线下物料（名片、展架）扫码直达分站或广告页
7. **微信支付**：未来收费广告可直接通过小程序微信支付完成

## 二、整体架构

### 2.1 技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 小程序框架 | uni-app（推荐）或原生微信小程序 | uni-app 可同时输出微信/支付宝/H5，扩展性好 |
| UI 组件库 | uView UI / Vant Weapp | 移动端组件成熟稳定 |
| 状态管理 | Pinia（uni-app）/ 小程序原生 globalData | 轻量状态管理 |
| 网络请求 | uni.request / wx.request 封装 | 统一拦截、Token 注入 |
| 地图/定位 | 微信定位 API + 腾讯地图 SDK | 城市级定位 |
| 后端 API | 复用现有 Java 后端 | 同一套 RESTful 接口，加小程序登录接口 |

## 三、小程序页面结构与导航设计

### 3.1 页面结构总览

```
TabBar（底部导航，3个Tab）
├── 首页 Tab (/pages/home/index)
│   ├── 自动定位 → 分站首页 → 广告展示
│   └── 快捷入口：招商入驻 / 广告投放
├── 分站 Tab (/pages/city/index)
│   └── 城市选择 → 切换分站
└── 我的 Tab (/pages/mine/index)
    ├── 微信登录
    ├── 我的分站记忆
    ├── 我的登记记录
    └── 联系客服

子页面（非 Tab 页）
├── /pages/station/detail      分站首页（完整广告展示）
├── /pages/ad/detail           广告详情页（点击广告进入）
├── /pages/inquiry/submit      招商登记提交页
├── /pages/demand/submit       广告需求登记提交页
├── /pages/inquiry/list        我的招商登记记录
├── /pages/demand/list         我的广告需求记录
└── /pages/webview/index       WebView 页面（打开外部链接）
```

### 3.2 底部 TabBar 设计

```
┌──────────────────────────────────────────────┐
│                                              │
│              页面内容区域                      │
│                                              │
├──────────────┬──────────────┬────────────────┤

│    首页      │    分站       │     我的       │
```

- **首页**：当前分站的广告内容展示（核心页面，用户 80% 时间在此）

#### 设计要点

- **精准定位**：首次打开调用 `wx.getLocation` 获取 GPS 坐标 → 逆地理编码获取城市 → 匹配分站。精度远超 PC 端的 IP 定位
- **金刚区**：4 个圆形图标快捷入口，"招商入驻"和"广告投放"放在最醒目位置
- **Banner**：全宽轮播，支持左右手势滑动，自动播放间隔 4 秒
- **推荐企业**：2 列瀑布流网格，卡片圆角 12px，有微阴影
- **列表广告**：无限滚动加载（触底自动加载更多），替代 PC 端的分页
- **下拉刷新**：支持下拉刷新整个页面广告数据

5. **电话直拨**：小程序可直接调起拨号，PC 端做不到

1. **微信手机号快速填充**：调用 `wx.getPhoneNumber` 一键获取用户绑定的手机号，用户无需手动输入，**大幅提高表单转化率**
2. **自动定位城市**：GPS 定位自动填充城市，无需手动选
3. **无需验证码**：小程序端用户已经过微信实名认证，加上微信环境本身的安全机制，可用**微信登录态 + 频率限制**替代图形验证码，进一步降低提交门槛
4. **订阅消息**：提交后引导用户订阅消息，后续可推送处理进展通知

## 五、微信能力深度集成

这是小程序相比 PC 端最大的差异化优势，建议充分利用以下微信能力：

### 5.1 微信登录（替代传统注册）

```
用户打开小程序
    │
    ▼
wx.login() 获取 code
    │
    ▼
发送 code 到后端
    │
    ▼
后端调用微信 auth.code2Session
获取 openid + session_key
    │
    ▼
创建/匹配用户 → 返回 token
    │
    ▼
前端存储 token → 登录完成
```

- 用户**无需注册**，微信一键授权即可
- 后端新增 `hdz_mp_user` 表存储 openid 与现有用户的映射
- 首次使用时通过 `wx.getUserProfile` 获取昵称头像

### 5.2 微信手机号快速获取

```
用户填写登记表单时
    │
    ▼
点击"使用微信手机号"按钮
    │
    ▼
<button open-type="getPhoneNumber"> 触发
    │
    ▼
wx.getPhoneNumber 回调 → 获取加密数据
    │
    ▼
发送到后端解密 → 获取手机号
    │
    ▼
自动填入表单的"联系电话"字段
```

**价值**：将招商登记/广告需求登记的表单填写时间从 60 秒缩短到 10 秒内，表单提交转化率预计提升 40%+。

### 5.3 精准定位

```
wx.getLocation({
  type: 'gcj02',    // 国测局坐标
  success(res) {
    // res.latitude, res.longitude
    // 逆地理编码 → 获取城市信息 → 匹配分站
  }
})
```

| 对比维度 | PC 端（IP 定位） | 小程序（GPS 定位） |
|---------|-----------------|-------------------|
| 精度 | 城市级（偶尔错误） | 街道级（几乎不会错） |
| 用户感知 | 无感知，可能定位到错误城市 | 明确授权，用户信任度高 |
| 首次体验 | 可能需要手动切换城市 | 直接定位到正确分站 |

### 6.1 hdz_mp_user（小程序用户表）

```sql
CREATE TABLE `hdz_mp_user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  `openid` VARCHAR(64) NOT NULL COMMENT '微信openid',
  `unionid` VARCHAR(64) DEFAULT NULL COMMENT '微信unionid',
  `user_id` BIGINT DEFAULT NULL COMMENT '关联平台用户ID(如有)',
  `nickname` VARCHAR(64) DEFAULT NULL COMMENT '微信昵称',
  `avatar_url` VARCHAR(512) DEFAULT NULL COMMENT '头像URL',
  `phone` VARCHAR(20) DEFAULT NULL COMMENT '手机号(授权获取)',
  `last_station_code` VARCHAR(32) DEFAULT NULL COMMENT '上次访问分站编码',
  `last_login_time` DATETIME DEFAULT NULL COMMENT '最后登录时间',
  `login_count` INT NOT NULL DEFAULT 0 COMMENT '登录次数',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
```

## 九、性能优化建议

### 9.1 小程序包体积控制

| 策略 | 说明 |
|------|------|
| 分包加载 | 首页放主包（< 2MB），城市选择/登记/详情放子包 |
| 图片 CDN | 所有图片走 CDN 加速，小程序包内不放图片 |
| 按需引入组件 | UI 组件库按需引入，不全量引入 |

### 9.2 启动性能

| 策略 | 说明 |
|------|------|
| 预请求 | onLaunch 阶段并行发起定位请求 + 分站数据请求 |
| 骨架屏 | 首页加载时显示骨架屏，减少白屏感知 |
| 缓存策略 | 分站数据、广告数据使用 wx.setStorageSync 本地缓存，先展示缓存再刷新 |

### 9.3 列表性能

| 策略 | 说明 |
|------|------|
| 虚拟列表 | 列表广告超过 50 条时使用虚拟列表渲染 |
| 图片懒加载 | 使用 `lazy-load` 属性，进入视窗才加载图片 |
| 分页加载 | 每次加载 10 条，触底加载更多 |

## 十一、总结与建议

### 小程序端的 3 个核心竞争力

1. **零门槛触达**：微信一键登录 + GPS 定位 + 手机号快填 → 用户从打开到提交登记可在 30 秒内完成
2. **社交裂变**：广告详情/分站首页可分享到微信群和朋友圈 → 带来免费的社交流量
3. **精准通知闭环**：订阅消息推送处理进展 → 用户再次打开小程序 → 形成使用闭环

### 优先级建议

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 必做 | 分站首页 + 广告展示 | 核心功能 |
| P0 必做 | 微信登录 + GPS 定位 | 小程序基础能力 |
| P0 必做 | 招商/需求登记 + 手机号快填 | 核心转化路径，小程序的最大优势 |
| P1 重要 | 分享裂变（好友/群/海报） | 核心增长手段 |
| P1 重要 | 广告详情页 + 一键拨号 | 提升广告价值 |
| P1 重要 | 订阅消息通知 | 用户回访闭环 |
| P2 可选 | 微信客服 | 替代传统客服 |
| P2 可选 | 我的登记记录查看 | 用户体验优化 |
| P3 后续 | 微信支付（收费广告） | 未来商业化 |
| P3 后续 | 小程序直播（招商宣讲） | 未来扩展 |
