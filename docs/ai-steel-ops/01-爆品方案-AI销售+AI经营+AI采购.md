# 01 · 爆品方案：AI 销售 + AI 经营 + AI 采购

## 1. 市场判断：客户现在为什么会掏钱

| 市场事实 | 对钢贸商的直接影响 | 对产品的含义 |
|---|---|---|
| 大量企业退出，行业出清 | 剩下的是「活下来的」：现金流紧、人少、不敢扩张 | 卖「省人、少亏」比卖「增长」好卖；按吨付费比席位费好卖 |
| 库存量下降约 1/3 | 自有库存覆盖不了客户询的规格，**接单必须靠调货**；库存结构错配（有的压、有的缺） | 报价不能只看自己仓，要同时看上游 / 平台货源；老库存要出清 |
| 需求零碎化 | 单均吨位下降，一张单 3–15 吨、多品种混配常见；**配货和运费成了决定赚不赚钱的变量** | 报价必须含运费 / 拼车 / 起订量，否则报出去就亏 |
| 供大于求 | 客户货比三家，报价快慢 = 成交与否；价格竞争激烈，毛利薄 | 「快 + 不报错 + 不报亏」是刚需，报价守门是刚需 |
| 账期普遍、逾期增多 | 资金成本直接吃掉毛利；放账风险上升 | 到岸成本要含资金成本；信用守门要进报价流程 |

一句话：**客户当下的痛点不是「没流量 / 没内容」，而是「来了询价不敢接、接了不知道赚不赚、小单不知道怎么送」**。

## 2. 两个方向的对比

| 维度 | 方向 1：销售 + 经营 + **运营** | 方向 2：销售 + 经营 + **采购** |
|---|---|---|
| 客户听到后第一反应 | 「做内容、做社群、激活老客户」——好像有用，但说不出下个月多赚多少 | 「来单秒报价、自动比价、小单给我配好车」——直接对应今天的烦恼 |
| 价值兑现时间 | 慢，需要 1–3 个月内容和运营积累 | 快，上线当天第一条询价就能看到报价和毛利 |
| 可量化指标 | 触达量、活跃度、激活率（间接） | 报价用时、自动发出率、报价后成交率、单均毛利、运费占比（直接） |
| 竞品 / 替代品 | SCRM、企微工具、群发工具很多 | 钢贸进销存只管记账，不管「怎么接这单」；几乎空白 |
| 数据壁垒 | 弱，内容和话术易复制 | 强：客户历史成交价、上游报价、拼车窗口、平台货源，越用越准 |
| 与货袋子平台的协同 | 弱 | 强：平台货源直接成为报价货源 → 撮合 GMV；拼车 → 物流撮合 |
| 风险 | 效果难归因，续费难 | 规则不准会报亏（靠守门和人工确认兜底） |

**方向 1 里真正有价值的两件事**——沉睡客户激活、跟进策略与话术精准化——本质属于「销售」，不是「运营」。获客模块（`docs/ai-acquisition` 03/04 分册）已经设计了 SOP 引擎、唤醒触发、话术库，直接作为 AI 销售的跟进层复用即可。方向 1 剩下的「内容生产 / 社群运营 / 朋友圈」作为第二年增值包。

## 3. 产品定位与三模块定义

> 一句话定位：**钢贸商的「接单大脑」——客户一句话询价，30 秒给出能赚钱、能送到的报价。**

```
                 ┌──────────────── AI 销售 ────────────────┐
  询价进来  →  识别需求 → [接单方案引擎] → 报价 → 发出 → 跟单 → 成交
                                  ↑                              ↓
                 ┌──────────── AI 采购 ────────────┐    ┌──── AI 经营 ────┐
                 库存 · 上游报价 · 平台货源 · 物流 · 拼车窗口 · 信用    报价/成交/毛利/运费/库龄看板
```

### 3.1 AI 销售（接单 + 跟进）
| 能力 | 说明 | 复用 / 新增 |
|---|---|---|
| 询价接入 | 微信 / 企微 / 电话转写 / 语音 / 截图 OCR / 平台询价，统一成 RFQ | 新增（接入层复用获客模块的会话工作台与投喂箱） |
| 需求解析 | 一句话 → 规格行（品名 / 材质 / 规格 / 数量）、交付地与期限、付款方式、信号（提到老价格 / 急 / 试单） | 新增，规则见 02 §2 |
| 秒报价 | 调用接单方案引擎，得到带毛利、带交付方式的方案与报价单文本 | 新增（本方案核心） |
| 报价守门 | 自动发出 / 需确认 / 转人工三级结论与原因码 | 新增，规则见 02 §7 |
| 报价跟单 | 发出后自动进入「报价跟单 SOP」：2 小时未回复提醒 → 电话 → 过期退回 | 复用获客模块 SOP 引擎（新增 SOP 类型 QUOTE_FOLLOW） |
| 还价处理 | 让价不低于毛利下限，超出转经理 | 新增 |
| 沉睡客户激活 | 按「上次成交规格 + 当前行情 + 库存出清」生成唤醒话术，批量触达 | 复用获客模块唤醒触发 / 话术库，增加「行情 + 库存」变量 |
| 精准跟进 | 按客户等级、项目阶段、历史成交品类给跟进策略和话术 | 复用获客模块 SOP / 话术库 |

### 3.2 AI 采购（配货 + 比价 + 物流）
| 能力 | 说明 |
|---|---|
| 货源池 | 自有库存（含锁定 / 库龄 / 加权成本）、上游每日报价（AI 从微信 / 表格抽取）、**货袋子平台其他商家挂牌**、市场指数 |
| 到岸比价 | 不是比「裸价」，比 **到岸成本** = 货源价 + 运费 + 装卸 + 平台服务费 + 账期资金成本 + 起订量余量持有成本 |
| 配货优先级 | 自有库存（老库存优先）→ 平台货源 → 上游；缺货用替代规格（需客户确认） |
| 五种交付方式 | 专车直送 / 市区配送（整单一车）/ 拼车窗口 / 货源直发 / 客户自提，每行各算一遍 |
| 拼单拼车 | 维护「已排定车辆的剩余吨位」窗口；零碎单优先搭车；多行同仓合并一车分摊运费 |
| 起订量处理 | 上游有起订量而客户要得少：算「多买入库」的持有成本，提示销售「建议客户加量到起订量」或确认余量可销 |
| 接单后动作 | 报价被接受自动生成：出库单 / 采购单 / 拼车任务 / 自提通知 / 入库单（余量挂牌到平台） |
| 周转建议 | 库龄 > N 天的库存在报价时自动让利出清；经营看板提示「该补 / 该清」 |

### 3.3 AI 经营（看得见赚没赚）
一期只做两张卡 + 一张看板：
- 报价漏斗：询价 → 报价 → 接受，分销售 / 分客户等级 / 分来源；自动发出率；首次报价用时。
- 毛利与运费：每单、每吨毛利；运费占比；拼车节省金额；老库存出清吨位。
- 经营看板：库存结构（有 / 缺 / 压）、信用占用与逾期、上游报价更新率。

## 4. 爆点「秒报价」端到端流程

```
① 询价进入   微信消息 / 语音 / 电话转写 / 企微 / 平台询价  → 自动建 RFQ，关联客户与线索
② 识别       规格行 + 数量 + 交付地 / 期限 + 付款方式 + 信号（老价格 / 急 / 试单）；置信度 < 80% 转人工核对
③ 配货比价   每行 × （自有 / 平台 / 上游）×（专车 / 拼车 / 直发 / 自提）→ 到岸成本 → 定价 → 毛利
④ 组方案     A 成本最优 · F 专车同车分摊 · B 最快 · C 自提 · D 替代 / 部分 · E 全拼车 → 打分 → 推荐
⑤ 守门       AUTO_SEND（直接发） / NEED_REVIEW（销售点一下确认） / MANUAL（转经理）
⑥ 发出       微信 / 企微文本一键发送；企微 H5 可在手机上确认
⑦ 跟单       2 小时未回复提醒 → 电话 → 4 小时过期退回队列；还价不低于毛利下限
⑧ 成交       自动生成出库 / 采购 / 拼车 / 自提 / 入库任务；库存扣减；进经营看板
```

**演示口径（种子客户第一次看）**：拿客户昨天微信里一条真实询价（例：「20 的螺纹来 8 吨，12 的盘螺 5 吨，送相城产业园工地，最好明天到。老价格还能做吗？」），当场得到：螺纹 8 吨走明天上午去产业园的拼车（运费 25 元/吨），盘螺 5 吨自有没货、上游起订 10 吨、改平台商家直发（25 元/吨不过手），合计 13 吨 ¥50,410，毛利 ¥507；系统标记「客户提到老价格 → 需确认让价幅度」；销售点确认发出；两小时后没回系统提醒。详细数字见 02 §12。

## 5. 一期范围与砍法

| 做 | 不做（二期 / 增值包） |
|---|---|
| 报价工作台（询价队列 / 识别 / 方案 / 报价单 / 规则参数 / 报价记录） | 内容生产、朋友圈、社群运营 |
| 接单方案引擎 v1（02 分册全部规则） | 同行报价爬取（拿不到，不做） |
| 货源与库存页（手工 + Excel 导入 + 出库扣减；上游报价 AI 抽取） | ERP / 进销存实时对接（预留接口） |
| 拼车看板（窗口维护 + 零碎单归集） | 车队 TMS、GPS 跟踪 |
| 经营看板两张卡 | 财务对账、开票 |
| 企微 H5：报价确认 / 发送 | 个微 RPA（可选，仅用于读询价） |
| 复用获客模块：线索 / 客户 / SOP / 话术 / 投喂箱 | 新建 CRM |

砍的原则：**凡是不直接缩短「询价 → 带毛利的报价 → 成交」这条线的，一期都不做。**

## 6. 定价与种子客户

### 6.1 定价（待确认 Q22）
| 模式 | 适用 | 说明 |
|---|---|---|
| A 按成交吨位 | 试用期 / 小商户 | 1–2 元/成交吨；客户心理：「一吨赚 30，给你 1 块」 |
| B 月包量 | 主推 | 如 3,000 吨/月封顶 3,000–5,000 元/月；超量按吨 |
| 平台服务费 | 补充 | 用平台货源成交，向供货商家收 5 元/吨（已计入报价引擎到岸价） |

不按席位：客户销售人数在收缩，席位费与客户利益相反。

### 6.1a 管型材商的适配（v0.9.1）
管型材 / 管件商（量小而杂、一单十几行、很多小管件）与建材商共用同一条主线，但用**第二套参数包 + 解析器扩展**：支 / 根 / 米按理重换算、寸 / DN 识别、管件按个 / 片与毛利率定价、同市场档口调货、整单一辆小车（三轮 / 4.2 m / 6.8 m）配送、运费上限守门。对他们的爆点说法是「一句话开 20 行单：自动换算理重、自动找货、一车送完、不报亏」。规则见 02 分册 §16，演示见 `quote.html?rfq=Q7`。

### 6.2 种子客户画像（首批 3–5 家）
- 建材 / 板材商：年销 2–10 万吨，3–15 名销售，经营 3 个以上品类（建材 + 板材 / 型材）。
- 管型材商（Q23 若选 B）：钢材市场内有档口 + 小仓，SKU 数千、日均 20–50 单、单均 1–5 t，开单靠人工查理重表。
- 有自有仓但库存覆盖不了询价（调货比例 > 30%）。
- 微信询价为主，当前报价靠销售翻微信问采购、再问车队，平均 20–40 分钟。
- 老板亲自管价格 / 信用，愿意把「目标毛利 / 自动发出边界」写成规则。

### 6.3 成功指标（上线 30 天）
| 指标 | 基线 | 目标 |
|---|---|---|
| 首次报价用时 | 20–40 分钟 | < 3 分钟 |
| 自动发出率 | 0 | > 40% |
| 报价后 24 小时成交率 | 客户现状 | +20% |
| 零碎单（≤ 10 吨）运费占比 | 客户现状 | −15% |
| 报亏单（毛利 < 下限） | 客户现状 | 趋近 0（被守门拦下） |

## 7. 与货袋子平台 / 获客模块的关系

- **货袋子平台**：平台商家挂牌 = 报价引擎的 PLATFORM 货源；成交即撮合；余量「挂牌到平台待售」反向供货；拼车窗口未来可跨商家共享 → 物流撮合。这是方向 2 对平台的独特价值：**每一次报价都在给平台喂货源与需求数据**。
- **获客模块**（`docs/ai-acquisition`）：线索 / 客户 / 项目档案、会话工作台、SOP 引擎、话术库、企微 H5、投喂箱全部复用；本方案新增 RFQ、报价、货源、物流、信用等对象，并在会话工作台增加「生成报价」入口、在待办中增加 QUOTE_FOLLOW 类型。

## 8. 实施路线（按里程碑，不按日历）

| 里程碑 | 交付 | 验收 |
|---|---|---|
| M1 规则冻结 | 02 分册 v1.0、参数默认值、原因码表；3 家种子客户各 50 条历史询价回放 | 回放结果中销售认可率 ≥ 80% |
| M2 报价闭环 | 报价工作台 + 引擎 + 货源与库存页（手工 / 导入）+ 企微 H5 发送 + 报价跟单 SOP | 种子客户真实询价跑通，首次报价 < 3 分钟 |
| M3 采购与物流 | 上游报价 AI 抽取、平台货源接入、拼车看板、成交后任务生成 | 自动发出率 > 40%，零碎单运费占比下降 |
| M4 经营与定价 | 经营看板、按吨计费、ERP 接口预留 | 3 家种子客户续费 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 规则不准导致报亏 | 毛利下限 + 市场带 + 三级守门；一期默认偏保守（NEED_REVIEW 多、AUTO_SEND 少），随回放数据放宽 |
| 上游报价拿不全 / 过期 | 过期报价不用于自动报价（6 小时）；销售投喂为主、采购维护为辅；平台货源补位 |
| 库存数据不准（没对接 ERP） | 出库自动扣减 + 每日盘点提醒；关键规格「锁定量」单独维护；二期对接 |
| 客户不接受自提 / 替代规格 | 客户未提自提时不推荐自提方案（仅备选）；替代规格必须在报价单注明并等待确认 |
| 销售觉得被「管」 | 守门结论给的是「原因 + 怎么办」，不是拒绝；销售可调价，低于下限才找经理 |
| 平台货源的价格敏感 | 平台货源在客户视图不显示来源；内部视图显示服务费 |
