# 货袋子平台 — AI 货袋子获客系统 设计方案

> 项目：货袋子（huodaizi.com）  
> 模块：AI 货袋子获客系统（简称 **AI 获客**，模块代号 `hdz-ai-acquisition`）  
> 版本：v1.0（决策点 Q1–Q9 已于 2026-09-25 全部确认；下一步进入高保真原型）  
> 日期：2026-09-25  
> 技术栈：Java（Spring Boot + MyBatis-Plus + MySQL + Redis）+ Vue 3（Element Plus），作为货袋子平台的一个可嵌入模块

---

## 0. 一页结论

**AI 获客做的事，一句话：把"人在各平台找客户 → 一对一发消息 → 盯着回复 → 手工记表"这条链路，变成"系统抓意图线索 → 个性化触达 → 关键词/AI 自动跟进 → 自动记录与看板"的闭环，销售只处理高意向客户和复杂问题。**

本方案的核心设计决策（详见各分册）：

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| 1 | 模块形态 | 独立 Maven 子模块 `hdz-ai-acquisition`（包 `com.hdz.acquisition`，表前缀 `hdz_acq_`），前端为货袋子运营后台/商家后台中的独立路由模块 `/acquisition/*` | 与已有 `hdz-advertisement`、`hdz-leads`、`hdz-circle` 模块保持同一集成方式 |
| 2 | 多租户 | 以 **商家（merchant_id）** 为租户，销售（owner_user_id）为席位；平台按订阅收费 | 需求中"平台订阅费用"即 SaaS 模式，销售看板按人隔离 |
| 3 | 渠道分层 | **渠道抽象层 ChannelGateway + 适配器 SPI**。渠道按接入方式分三档：① 官方 API（企业微信客户联系、抖音开放平台、货袋子站内渠道）② HTTP/浏览器自动化（行业论坛、小红书网页版）③ **执行端 RPA**（个人微信、抖音 App、小红书 App，在工作手机/云手机上模拟真人操作，**一期交付，小号灰度起步**） | 微信个人号、抖音、小红书都**没有**官方接口允许抓评论区/自动私信，只能靠 RPA；而 RPA 是封号高风险项，必须与官方渠道解耦、可单独开关 |
| 4 | 执行端 | 服务端（Java）只做"编排 + 排队 + 风控节流 + 下发指令"，真正在 App 里点击/输入/发送的是 **执行端（获客助手 App，Android 无障碍服务）**，通过 WebSocket 长连接收任务、回传结果和截图证据 | 服务端不持有微信登录态，风险隔离；小号先跑、稳定后上主号 |
| 5 | AI 用在四处 | ① 意图识别与打分（抓到的评论是不是"求推荐/怎么报名/有没有货"）② 个性化消息生成（带昵称、来源、历史互动，必须过变量校验）③ 回复匹配（**关键词规则优先，LLM 语义兜底**，命中话术库）④ 自然语言 → 定时任务 Spec 解析（"每天早上 9 点抓取线索"→ cron + 动作 + 参数，确认后生效） | 规则可控、可解释；LLM 只在规则未命中时兜底，且报价/合同/承诺效果一律转人工 |
| 6 | 复用已有能力 | 直接复用海报系统的 `poster_session / poster_share`（分享即出渠道码）做海报分发与扫码归因；复用企业资料库 `knowledge_item` 做话术 RAG；复用 `ModelGateway` 做模型路由；沉淀的线索回流平台"线索中心" | 不重复建设，海报扫码回来的咨询自动成为线索 |
| 7 | 五张业务表 | 需求中的"线索表、触达表、话术库、跟进表、看板表"为**系统预置表**（`hdz_acq_lead / outreach / script / follow_up / stat_daily`），商家不建表，只做字段扩展（`ext_json`）与开通向导 | 需求描述的"第一小时建表"在 SaaS 里应变成"开通即用" |
| 8 | 风控与合规 | 三条硬约束：**频率上限 + 随机延迟 + 拟人化时段**由服务端统一节流；**每条消息必须含 ≥1 个个性化变量**，否则不允许发送；**一次触达无回复 ≤ N 次后停止**，用户表态拒绝即进黑名单。报价、合同、承诺效果进入**人工审核队列** | 对应"避坑指南"四条；同时满足《个人信息保护法》最小必要、《广告法》与平台规范 |
| 9 | 跟进引擎支持分支编排 | 跟进分两层：**被动层** `ReplyMatcher`（客户说话→秒级回话术）+ **主动层** `FlowEngine`（跟进流程 / SOP，JSON DAG 定义 + 持久化实例，事件驱动 + 定时唤醒）。一期最小节点集：Trigger / Send / Wait / WaitForReply（未回复、拒绝、按回复类别、按实体分支）/ Branch / HumanTask / SetStage / Tag / Notify / GoTo / End；纵向树编辑器；预置一条"标准跟进 SOP"。自研轻量解释器，不引入 BPMN 引擎 | 真实销售 SOP 是分叉的（无回复发案例、问价转人工、再考虑 7 天后发活动），线性链表达不了；话术上的 `follow_up_after_hours` 保留为无流程时的简易兼容 |

**一期范围（按 2026-09-25 决策确认，详见 07 分册）**：一期同时交付两条线——**低风险渠道闭环**（企业微信 + 货袋子站内 + 行业论坛 + 抖音/小红书官方能力）与**执行端 RPA 渠道**（自研 Android 获客助手 App；个人微信 群/朋友圈/私聊/群回复/发朋友圈；抖音/小红书 自家内容评论区 + **任意关键词下他人评论区抓取**）。RPA 能力在一期内按"小号 → 灰度商家 → 全量"推进，他人评论区抓取默认关闭、需商家显式开启并接受风险告知，配额取平台下限。低风险线先行交付，RPA 线紧随。

## 2. 决策点（已全部确认，2026-09-25）

| # | 问题 | 结论 | 对设计的影响 |
|---|------|------|-------------|
| Q1 | 微信渠道优先级 | **A + B**：企业微信官方 API 优先，**个人微信 RPA 一期同步交付** | 07 分册一期拆为"低风险渠道线 + RPA 执行端线"两条并行交付线；个人微信 RPA 一期以小号灰度起步 |
| Q2 | 执行端形态 | **A**：自研 Android 获客助手 App（工作手机/云手机均可安装） | 云手机仅作为部署形态选项，不采购厂商控制端；PC 微信 RPA 不做 |
| Q3 | 抖音/小红书评论区抓取 | **A + B**：官方开放平台能力 + 自家内容评论区 RPA，**且一期支持任意关键词下他人评论区抓取（RPA）** | 他人评论区抓取作为独立能力开关（`CAPTURE_PUBLIC_COMMENTS`），默认关闭，需商家开启并接受风险告知；配额取平台下限；运营可按平台一键关停 |
| Q4 | 使用者 | **A（同时满足 B）**：SaaS 给入驻商家用；货袋子自有销售团队作为一个商家使用 | 多租户设计不变 |
| Q5 | 大模型 | **是**：复用海报系统 ModelGateway | 不变 |
| Q6 | 线索回流 | **是，单向同步**到平台线索中心 | 不变 |
| Q7 | 海报分发目标 | **不含抖音**：微信群/朋友圈（企微 API + 个人微信 RPA）、小红书、行业论坛 | 不变 |
| Q8 | "销售时间分配"指标 | **A + B**：系统不自动测量、不进入核心指标；**提供销售每日手工填报**，看板以独立"人工填报"卡片展示（可按商家开关） | 新增 `hdz_acq_sales_daily_report` 表与填报接口/页面；`stat_daily` 不混入 |
| Q9 | 跟进引擎分支编排 | **A**：一期实现 FlowEngine 核心 + 最小节点集 + 纵向树编辑器 | 见决策 9 |
