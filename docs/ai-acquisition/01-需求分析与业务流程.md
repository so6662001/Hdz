# 01 · 需求分析与业务流程

> 所属：AI 货袋子获客系统 v0.1  
> 目的：把需求原文（进场当天四步、当天下午四小时、一周数据、底层逻辑、避坑指南）逐条翻译成可开发、可验收的功能，并明确边界。

## 1. 需求逐条拆解

### 1.1 第一步：自动抓取线索

| 需求原文 | 翻译成功能 | 说明 / 约束 |
|---------|-----------|------------|
| 自动扫描指定关键词的评论区、话题页 | **抓取规则（CaptureRule）**：平台 × 范围（评论区/话题页/帖子列表）× 关键词组 × 意图短语 × 时间窗 | 抖音/小红书没有官方"按关键词拉他人评论区"接口，需 RPA 执行端在 App 内搜索→进入内容→滚动读取评论（见 05 分册）；行业论坛多为网页，可用 HTTP/浏览器自动化 |
| 社群成员、微信群 | 执行端读取群成员列表与群聊消息流；企业微信可用官方"客户群"接口 | 群成员只有昵称/群备注，**没有手机号**；只有说出意图话的人才成为线索，不把整个群成员表当线索 |
| 微信朋友圈 | 执行端浏览朋友圈时间线，识别含意图的动态与评论 | 朋友圈只能看到已是好友的人，属于"存量激活"而非新客 |
| 抓取"求推荐""怎么报名""有没有资料""有没有货"等意图明显的用户 | **意图识别**：关键词/正则命中 → 快速判定；未命中时 LLM 分类（需求/询价/求资料/求推荐/无关）并输出 0~100 意图分 | 意图分是后续"触达顺序"和"高意向"判断的基础 |
| 自动录入线索表 | 去重（平台 + 平台用户 ID + 商家）→ 建线索 → 记原文、链接、截图 → 自动分配销售（轮询/按区域/按产品线） | 每条线索必须带**可回溯的来源**（原帖链接或截图），供销售判断与合规留痕 |

### 1.2 第二步：自动触达

| 需求原文 | 翻译成功能 | 说明 / 约束 |
|---------|-----------|------------|
| 读取线索表，按预设规则发送个性化消息 | **触达任务**：筛选条件（新线索、意图分 ≥ X、渠道、未触达）→ 选话术模板 → 变量渲染 → 排队 → 风控节流 → 下发渠道 | 变量：`{昵称}` `{来源渠道}` `{来源内容摘要}` `{历史互动}` `{产品/品类}` `{销售姓名}` `{公司}`；**渲染后必须至少命中 1 个个性化变量**，否则任务级阻断（对应需求里"漏了昵称变量"的坑） |
| 不是群发模板，是带昵称、来源、历史互动的消息 | 模板 + LLM 改写两种模式：**模板模式**只替换变量；**AI 润色模式**把变量和话术要点交给 LLM 生成一句自然话术，再过敏感词与长度校验 | AI 润色的结果先进"待发送预览"，商家可开关"AI 润色需人工确认" |
| 朋友圈自动回消息、社群自动回消息 | 属于"自动跟进"的入站处理：监听朋友圈评论/群消息 → 匹配话术 → 回复（群内回复或转私聊） | 群内自动回复默认只回复 @ 自己或命中意图关键词的消息，避免刷屏 |
| 海报自动发送到微信社群、朋友圈、小红书、行业论坛 | **海报分发任务**：选择海报（海报系统 `poster_session`）→ 选择目标（群列表 / 朋友圈 / 小红书账号 / 论坛版块）→ 定时 → 按渠道出渠道码图（复用 `poster_share`）→ 下发执行端发布 → 回执 | 扫码后落地页 `/q/{code}` 已能归因到渠道，海报带来的咨询自动成为线索 |

### 1.3 第三步：自动跟进

| 需求原文 | 翻译成功能 | 说明 / 约束 |
|---------|-----------|------------|
| 客户回复后按关键词匹配话术库 | **回复匹配引擎**：① 黑名单/拒绝词（"别发了""不需要"）→ 停止并拉黑；② 关键词/正则规则（价格、报价、多少钱 → 报价话术）；③ 未命中 → LLM 语义分类到话术库分类；④ 仍无 → 转人工 | 规则优先、LLM 兜底，所有匹配结果可解释（记录命中的规则/分类和置信度） |
| 问价格 → 发报价话术 | 报价类话术标记 `requires_human=true`：系统只发"收到，稍后给您报价"的过渡话术，同时生成**审核单**给销售填写价格 | 对应避坑指南第三条：报价、合同、承诺效果必须人工 |
| 问案例 → 发案例链接 | 话术可挂附件：链接、图片、海报、资料 PDF、企业资料库条目 | 案例链接可带 UTM/渠道码，回流点击数据 |
| 说"再考虑" → 3 天后自动跟进 | 话术带**后续动作**：`follow_up_after=3d`，生成跟进任务；到期由"跟进未回复"任务发送二次话术 | 二次跟进最多 N 次（默认 2），仍无回复→标记"沉默"，不再打扰 |
| 销售只处理高意向客户和复杂问题 | **升级规则**：意图分 ≥ 80、提到数量/规格/交期、连续 2 轮未命中话术、客户要求人工 → 推企微通知给销售，会话进入"待人工"状态 | 复用已有企业微信通知 SDK |

### 1.4 第四步：自动记录

| 需求原文 | 翻译成功能 |
|---------|-----------|
| 所有触达、回复、跟进自动写表 | 线索时间线（`lead_event`，追加不可改）+ 触达表 + 会话消息表 + 跟进表，全部由引擎自动写入，人工操作也记录 |
| 看板一眼看到谁该跟进、谁快成交、谁已流失 | **看板**：今日待跟进列表（按到期时间）、阶段漏斗（新线索→已触达→已回复→高意向→成交/流失）、渠道对比、话术回复率排行、账号健康度；日报表 `stat_daily` 每日 17:00 聚合 + 实时补算 |

### 1.5 "当天下午跑通"→ 商家开通向导

需求描述的四小时流程，在 SaaS 模块中对应一个**四步向导**（无需商家建表）：

| 需求原文 | 向导步骤 | 系统行为 |
|---------|---------|---------|
| 第一小时：建线索表、触达表、话术库、跟进表、看板表 | **步骤 1 · 初始化知识库** | 表由系统预置；向导让商家填写：公司简介、主营产品/品类、销售名单、默认变量值；导入话术库模板（钢材贸易/加工/物流等行业包）；可添加自定义字段（`ext_json`） |
| 第二小时：创建定时任务，每个任务用自然语言描述 | **步骤 2 · 配置自动化任务** | 输入"每天早上 9 点抓取线索""10 点发送触达""下午 2 点跟进未回复客户""下午 5 点更新看板"→ LLM 解析为结构化 Spec（cron、动作、筛选条件、话术、渠道）→ **确认卡片**展示解析结果 → 保存生效 |
| 第三小时：绑定公司微信号、抖音号、小红书号 | **步骤 3 · 接入渠道** | 企业微信：扫码授权；个人微信/抖音/小红书：下载获客助手 App 到工作手机 → 扫码绑定设备 → 在 App 内登录账号 → 设备心跳上线；为每个账号设置风控档位（小号/主号） |
| 第四小时：手动添加 5 条测试线索跑全流程 | **步骤 4 · 测试运行** | 手工新增/导入 5 条测试线索（可标记 `is_test`，只发给自己的测试号）→ 触达任务**试运行（dry-run）**先预览渲染文本 → 变量缺失即提示"消息缺少昵称变量" → 修改指令重跑 → 真实发送 → 模拟回复 → 看板看到数据 |

## 2. 角色与使用场景

| 角色 | 所在端 | 核心场景 |
|------|------|---------|
| **商家管理员**（老板/销售主管） | 商家后台 · 获客模块 | 开通向导、绑定渠道、维护话术库、配置任务与风控、看整体看板、审核报价 |
| **销售** | 商家后台 · 获客模块（PC）+ 企微通知（移动） | 看"我的待跟进"、处理待人工会话、填写报价审核、手动记录成交、看自己的看板 |
| **平台运营**（货袋子） | 运营后台 | 订阅开通与席位管理、行业话术包维护、全平台风控总闸、账号封禁告警、用量与成本统计 |
| **执行端设备** | 工作手机/云手机上的获客助手 App | 接收指令、在微信/抖音/小红书 App 内操作、回传结果 |
| **潜在客户** | 各社交平台 | 被抓取（仅公开的意图表达）、被触达、回复、扫码、成交 |

## 3. 端到端业务流程

### 3.1 总览：四步闭环

```
   ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
   │ ① 自动抓取    │───▶│ ② 自动触达    │───▶│ ③ 自动跟进    │───▶│ ④ 自动记录    │
   │ 关键词/意图   │    │ 个性化消息    │    │ 关键词匹配话术 │    │ 时间线/看板   │
   │ → 线索表     │    │ 海报分发     │    │ 定时二次跟进  │    │ → 日报表     │
   └──────┬───────┘    └──────┬───────┘    └──────┬───────┘    └──────┬───────┘
          │                   │                   │                   │
          ▼                   ▼                   ▼                   ▼
    hdz_acq_lead        hdz_acq_outreach     hdz_acq_follow_up   hdz_acq_stat_daily
    hdz_acq_capture_raw hdz_acq_message      hdz_acq_approval    hdz_acq_lead_event
          ▲                                        │
          └──── 海报扫码咨询 / 站内询价 回流为线索 ◀──┘
```

### 3.2 抓取流程

```
定时任务(09:00) / 手动触发
      │
      ▼
读取商家启用的抓取规则（平台、范围、关键词、意图短语）
      │
      ├─ 官方 API 渠道（企微客户群、货袋子圈子/询价）→ 直接拉取增量
      ├─ HTTP 渠道（行业论坛）→ 抓帖子/回帖列表
      └─ RPA 渠道（抖音/小红书/个人微信）→ 生成"采集指令"下发在线执行端
                                               │
                                               ▼
                                   执行端搜索关键词 → 进入内容 → 滚动读评论 → 回传（文本+作者+链接+截图）
      │
      ▼
写入 hdz_acq_capture_raw（原始记录，含 raw_hash 去重）
      │
      ▼
意图识别：关键词/正则 → 命中则 intent + score
          未命中 → LLM 分类（批量 20 条/次）→ intent + score + 理由
      │
      ├─ score < 阈值(默认 40) → 标记 IGNORED，不建线索
      ▼
线索去重：merchant_id + platform + platform_user_id（无 ID 时用 昵称+来源内容 hash）
      │
      ├─ 已存在 → 追加 lead_event(RECAPTURED)，刷新意图分与最近活跃
      └─ 新线索 → 建 hdz_acq_lead（stage=NEW）→ 自动分配 owner（轮询/规则）
      │
      ▼
写 lead_event(CAPTURED)；高意图(≥80)即时企微通知销售
```

### 3.3 触达流程

```
定时任务(10:00) / 手动选中线索触达
      │
      ▼
筛选：stage=NEW 且未触达、意图分≥X、渠道账号可用、不在黑名单、不在静默期
      │
      ▼
为每条线索选话术：任务指定 或 按 (渠道, 意图分类) 匹配"首触话术"
      │
      ▼
变量渲染 → 个性化校验（≥1 个个性化变量；无昵称时用"您好"降级但记 warning）
      │                       │
      │                       └─ 校验失败 → 任务失败并提示缺失变量（dry-run 阶段即暴露）
      ▼
可选：AI 润色（LLM）→ 敏感词/广告法禁用词过滤 → 长度校验
      │
      ▼
写 hdz_acq_outreach(status=QUEUED) → 入渠道账号发送队列（Redis）
      │
      ▼
风控节流器：按账号 每小时/每日上限、随机延迟 (min~max 秒)、活跃时段、新号养号曲线
      │
      ├─ 官方 API → 直接调用（企微 客户联系/群发）
      └─ RPA → 下发"发送指令"给绑定执行端 → 执行端回执（成功/失败/需验证码/被限制）
      │
      ▼
更新 outreach 状态（SENT / FAILED / BLOCKED）；lead.stage → CONTACTED；写 lead_event(OUTREACH_SENT)
      │
      ▼
失败分类：临时(网络) → 重试；账号被限制 → 账号熔断 + 告警；对方不可达 → 线索标记
```

### 3.4 回复与跟进流程

```
入站消息（执行端上报 / 企微回调 / 站内消息）
      │
      ▼
关联会话：platform + account + peer_id → conversation → lead
      │
      ▼
写 hdz_acq_message(direction=IN)；lead.stage 至少 → REPLIED；outreach.replied=1
      │
      ▼
① 拒绝/退订词命中？ ──是──▶ 拉黑 + stage=LOST(reason=REFUSED) + 停止所有跟进
      │否
② 关键词/正则规则匹配话术（按优先级）
      │未命中
③ LLM 语义分类 → 话术分类（置信度 ≥0.7 才采用）
      │未命中/低置信
④ 转人工：conversation.status=NEED_HUMAN，企微通知 owner
      │
      ▼（命中话术）
话术.requires_human？ ──是──▶ 发过渡话术 + 建 approval（报价/合同/承诺）→ 销售处理后由人工发送
      │否
自动回复（走与触达相同的渲染 → 校验 → 节流 → 发送链路）
      │
      ▼
话术.follow_up_after 存在？→ 建 hdz_acq_follow_up(due_at=now+N)
      │
      ▼
高意向判定：意图分 ≥80 或 提到 数量/规格/交期/地址 → stage=HOT → 企微通知 owner

定时任务(14:00) 跟进未回复：
  查 follow_up.due_at ≤ now 且 status=PENDING → 选二次跟进话术 → 走触达链路
  同一线索累计自动跟进 ≥ N(默认 2) 仍无回复 → stage=SILENT，进入静默期(默认 30 天)
```

### 3.5 记录与看板

- 每一次系统动作与人工动作都写 `hdz_acq_lead_event`（类型：CAPTURED / ASSIGNED / OUTREACH_SENT / REPLIED / SCRIPT_MATCHED / FOLLOW_UP_SCHEDULED / ESCALATED / APPROVAL_CREATED / STAGE_CHANGED / NOTE / WON / LOST），**只追加不修改**。
- 定时任务（17:00）聚合当日 `stat_daily`（按商家 × 销售 × 渠道），看板同时叠加当日实时计数（Redis 计数器）。
- 看板三问：**谁该跟进**（follow_up 到期 + NEED_HUMAN 会话）、**谁快成交**（stage=HOT，按意图分与最近活跃排序）、**谁已流失**（LOST/SILENT，带原因）。

## 4. 线索阶段状态机

```
NEW ──触达成功──▶ CONTACTED ──客户回复──▶ REPLIED ──高意向判定──▶ HOT ──人工标记──▶ WON
 │                    │                      │                     │
 │                    │ N 次无回复            │ 拒绝词/拉黑           │ 人工标记
 │                    ▼                      ▼                     ▼
 │                 SILENT ─────────────────▶ LOST ◀────────────────┘
 │                    │(静默期结束且再次抓到意图)
 └──意图分<阈值──▶ IGNORED   SILENT ──▶ NEW（重新激活）
```

- 任何阶段可由销售人工修改，修改记录进时间线。
- `WON` 需填写成交金额/品类（可选），用于看板成交统计。

## 5. KPI 与口径（对应"一周后的数据对比"）

| 指标 | 口径 | 数据来源 | 备注 |
|------|------|---------|------|
| 触达量 / 天 | 当日 `outreach.status=SENT` 去重线索数 | outreach | 目标 300+ 只是叙事目标，实际上限由风控策略决定 |
| 回复率 | 当日触达线索中 7 日内有入站消息的比例 | outreach + message | 按话术、渠道、销售三维拆分 |
| 高意向数 | stage 进入 HOT 的线索数 | lead_event | |
| 成交数 / 金额 | stage=WON 的线索数与填报金额 | lead | 成交由人工确认 |
| 线索成本 | 平台订阅费 ÷ 有效线索数 | 订阅 + lead | 用于对比广告投放 |
| 自动处理率 | 自动回复条数 ÷ 全部出站消息数 | message | 越高说明话术库覆盖越好 |
| 转人工率 | NEED_HUMAN 会话数 ÷ 有回复会话数 | conversation | |
| 账号健康度 | 账号 24h 内 BLOCKED/验证码 次数、当前熔断状态 | channel_account | 风控页 |
| 销售时间分配 | 系统无法测量 | — | 默认**不纳入**（README Q8） |

## 6. 需求边界（一期明确不做 / 有条件做）

| 项 | 结论 | 原因 |
|----|------|------|
| 抓取非公开信息（手机号、微信号）| **不做** | 《个人信息保护法》；线索只记录公开昵称、公开发言与链接，手机号仅在客户主动提供后由销售录入 |
| 无差别群发、给未表达意图的用户发消息 | **不做** | 避坑第一条；平台风控；`personalization_check` 强制 |
| AI 自动报价/承诺交期/签合同 | **不做** | 避坑第三条；一律 approval 转人工 |
| 抖音/小红书任意关键词下他人评论区的批量抓取 | **有条件**：仅 RPA 执行端、限速、二期灰度 | 平台风控最严；一期先做自家内容评论区 + 话题页浏览 |
| 一个执行端登录多个微信号并发操作 | **不做** | 一台设备一个微信号，模拟真人 |
| 越过平台验证码/滑块 | **不做** | 出现验证即熔断并通知人工处理 |
| 私域 SCRM 全套（客户标签体系、企微会话存档） | **不做** | 与本模块目标不同，后续可对接 |

## 7. 术语表

| 术语 | 含义 |
|------|------|
| 线索 Lead | 一个在某平台公开表达过需求意图、可被触达的账号 |
| 触达 Outreach | 系统或销售向线索首次/再次主动发出的消息 |
| 话术 Script | 可复用的消息模板，含变量、触发规则、附件、后续动作 |
| 跟进 FollowUp | 有到期时间的待办动作（自动或人工） |
| 渠道账号 ChannelAccount | 商家绑定的某平台账号（企微/个人微信/抖音/小红书/论坛） |
| 执行端 Executor | 装有获客助手 App 的工作手机/云手机，代替人在 App 内操作 |
| 自动化任务 AutomationJob | 由自然语言描述并解析为 cron + 动作的定时任务 |
| 渠道码 track_code | 海报系统"分享即出渠道码"机制中的二维码短链码，用于扫码归因 |
