# 08 · 钢材采购方线索渠道拓展方案

> 版本：v0.1（讨论稿，待确认后并入 01 / 02 / 05 分册）  
> 日期：2026-09-27  
> 目标客户：**钢材使用方**（施工总包 / 分包、钢结构与金属制品加工厂、机械与装备制造、下游二级配送与加工中心），而非同行贸易商  
> 输入：已有思路 —— 工程项目信息（住建公示、招投标）、下游制造企业开工与招标、企业工商变更、本地新注册加工厂与建筑公司

---

## 0. 一页结论

1. **先想清楚"钢在哪一刻被买"，再决定"去哪里找人"。** 钢材需求不是凭空冒出来的，它沿着一条固定链条往下传：土地 / 立项 → 设计出图 → 招标中标 → 施工许可 → 桩基 → 主体 → 二次结构 / 安装；工厂端是环评 / 备案 → 厂房建设 → 设备进场 → 投产扩产。每一个环节都有**公开留痕**，而且**越靠前的信号，竞争越少、越有时间做关系**；越靠后的信号（询价）越准，但已经是"比价局"。
2. 已有的四条思路都在"项目 / 企业"两条链上，是对的，但只覆盖了链条的**中段**（中标、施工许可、注册）。本方案向前补了**土地、立项、环评、规划许可、设计院、专项债 / 重点项目清单**，向后补了**分包中标、招聘信号、异业供应商、造价询价、老客户关系图谱**，横向补了**行业资质名录、许可证公示、央企集采平台、行情内容引流、线下扫街 OCR**。
3. 老销售最值钱的经验只有一句：**同一个工地上，混凝土、模板、脚手架、钢筋班组、监理、造价员比你更早知道什么时候要钢。** 把"异业联盟 + 介绍人分成"做进系统，是所有渠道里 ROI 最高、最难被同行复制的一条。
4. 渠道按"**需求前置期 × 转化率 × 自动化程度 × 合规风险**"排优先级：一期先接 **8 条公开结构化数据源**（四库一平台、招投标、环评、工商、信用中国许可、招聘、光伏 / 能源备案、重点项目清单）+ **1 条关系渠道**（介绍人 / 异业）+ **1 条自有渠道**（货袋子站内行为）；二期做设计院 / 造价 / 监理生态与行情内容引流；付费数据（工程情报、招标 API）按区域试点再放量。
5. 对 AI 获客系统的影响：新增 **"公开数据线索源"适配器族**（与社媒意图抓取并列），线索模型从"人"扩展为 **"项目 / 企业 / 人"三层**，评分增加 **用钢量估算、需求时间窗、决策链、信用风险、物流半径** 五个维度，首触话术从"看到您在 XX 问"扩展到"看到贵司中标 / 开工 / 扩产 XX"。

### 1.3 用钢量估算（经验区间，用于线索打分，需按本地项目校准）

| 类型 | 主要品类 | 经验用钢量 |
|------|----------|-----------|

| 商业 / 办公（框架、框剪） | 螺纹钢 / 盘螺 / 部分型钢 | 约 55–90 kg/㎡ |
| 轻钢厂房（门式刚架） | H 型钢 / C、Z 型钢 / 彩涂板 | 主结构约 30–60 kg/㎡ |
| 多层重型工业厂房 / 物流仓 | H 型钢 / 板材 / 钢筋 | 约 80–150 kg/㎡ |

## 2. 渠道全景：六族三十条

评分口径：前置期（越长越早介入）★=晚 → ★★★★=早；转化（★越多越准）；自动化（A 全自动 / S 半自动 / H 人做）；合规（🟢 公开政务数据或企业公开信息 / 🟡 需授权或付费 API、注意个人信息 / 🔴 不建议）。

## 4. 对 AI 获客系统的设计影响

### 4.1 线索模型：从"人"到"项目 / 企业 / 人"三层

现有 `hdz_acq_lead` 以"社媒上的一个人 + 一句话"为中心。项目族 / 企业族线索的主体是**项目**或**企业**，联系人是后来才补上的。建议：

- 新增 `hdz_acq_project`（项目档案）：project_name、owner_org（建设单位）、contractor_org（总包）、supervisor_org、designer_org、region、area_m2、structure_type、stage（LAND / APPROVED / EIA / BID / PERMIT / PILING / MAIN / FINISH）、est_tonnage、need_window_start / end、contract_amount、source_refs（来源记录 id 列表，多源合并）。
- 新增 `hdz_acq_company`（企业档案）：统一社会信用代码、行业、经营范围标签、资质列表、许可列表、注册资本与变更、招聘信号分、出口标记、信用风险（被执行 / 欠税 / 诉讼计数）。
- `hdz_acq_lead` 增加 `lead_type`（PERSON / COMPANY / PROJECT）、`project_id`、`company_id`、`role`（项目经理 / 材料员 / 采购 / 老板 / 厂长）、`decision_level`。一个项目可挂多个联系人线索，一个企业可挂多个项目。
- `source_type` 枚举扩展：PERMIT / BID / SUBCONTRACT_BID / EIA / LAND / KEY_PROJECT / ENERGY_FILING / BIZ_REG / LICENSE / QUALIFICATION / HIRING / REFERRAL / SITE_PHOTO / MARKET_REPORT / SEARCH。

### 4.2 渠道抽象层：新增"公开数据线索源"适配器族

在 `ChannelGateway` 之外（或并列）增加 `LeadSourceGateway` + `LeadSourceAdapter SPI`，特点是**只抓取不触达**、按计划任务运行、输出结构化记录：

- `PermitAdapter`（四库一平台 / 住建公示）、`BidAdapter`（公共资源交易 / 聚合 API）、`EiaAdapter`、`LandAdapter`、`KeyProjectImportAdapter`（Excel / 文本导入 + AI 抽取）、`EnergyFilingAdapter`、`BizRegAdapter`（企查查类 API）、`CreditLicenseAdapter`（信用中国）、`HiringAdapter`、`SiteOcrAdapter`（App 拍照 OCR）、`InternalBehaviorAdapter`（站内）。
- 统一输出 `RawRecord{source, external_id, entity_type, fields, raw_text, captured_at}` → `EntityResolver`（按信用代码 / 名称 / 地址合并到 project / company）→ `LeadScorer` → 线索池。
- 抓取策略：优先官方开放接口与付费授权 API；网页抓取只用于政务公开页面，遵守 robots 与频率；**不抓取需登录的商业平台**。

### 4.3 评分：五个新维度

| 维度 | 来源 | 作用 |
|------|------|------|
| 估算吨位 | 面积 × 结构系数、光伏 MW × 系数、合同额反推 | 排序：大项目优先分配给资深销售 |
| 需求时间窗 | 阶段 + 经验前置期（§1 表） | 决定首触时机与跟进 SOP（例如"施工许可后第 45 天提醒主体钢筋报价"） |
| 决策链完整度 | 是否已有项目经理 / 材料员 / 采购联系人 | 缺联系人的项目线索走"找人"任务而不是"发消息"任务 |
| 信用风险 | 工商风险：被执行、欠税、诉讼、经营异常 | 直接扣分或标红；钢贸的坏账比丢单更致命 |
| 物流半径 | 项目 / 企业地址到商家仓库距离 | 超出服务半径（默认 200 km，可配）的线索降权或推给平台其他商家 |

### 4.4 触达与跟进：按来源换话术、换 SOP

- 个性化变量扩展：`project_name`、`bid_amount`、`permit_date`、`company_change`（"新增钢结构工程专业承包资质"）、`hiring_signal`（"近期招聘 15 名焊工"）、`referrer_name`。首触话术从"看到您在 XX 问"变为"看到贵司中标 / 开工 / 扩产 XX，我们在 XX 有仓，HRB400 现货可当天送到"。`PersonalizationValidator` 规则同样适用：必须至少引用 1 个项目 / 企业事实。
- 触达方式：项目 / 企业线索的首触以**电话 + 企微 / 短信**为主（企业公开联系方式），社媒私信为辅；话术库增加"电话开场白 + 通话要点"类型，跟进流程增加 `Call` 节点（人工任务，记录通话结果）。
- 预置两条新 SOP：
  - **项目跟进 SOP**：施工许可 → 第 0 天找联系人（介绍人 / 铭牌 / 四库人员库）→ 第 7 天首触 → 第 30 天送样 / 报价 → 桩基结束前 30 天主体钢筋报价 → 主体期每两周行情早报 + 库存提醒 → 结构封顶转二次结构品类。
  - **新厂 / 扩产 SOP**：环评 / 注册 → 第 0 天建档 → 第 14 天拜访（园区 / 代账介绍）→ 厂房建设期跟钢结构分包 → 投产前 60 天原材料报价 → 投产后按月补货提醒。
- 介绍人机制：`hdz_acq_referrer`（介绍人：异业供应商 / 老客户 / 员工亲友）、`referral_code`、成交后按吨位 / 金额比例生成 `referral_settlement`，看板单列"介绍人渠道贡献"。

### 4.5 合规要点（补充 05 分册 §4）

- 政务公开数据（施工许可、中标、环评、许可双公示）可用于商业联络，但需**注明来源、按需保留**（项目结束后归档）。
- 企业公开联系方式用于 B2B 联络通常可接受；**项目经理 / 材料员的手机号属于个人信息**，需最小必要、首触即告知来源并提供拒绝方式；拒绝后全渠道拉黑（沿用现有黑名单机制）。
- 电话触达遵守骚扰电话治理要求：时段（9:00–20:00）、同一号码频次上限（建议每周 ≤ 1 次未接通重拨 ≤ 2 次）、来电显示企业名。
- 招聘平台、B2B 平台、行业站数据须遵守平台服务条款；付费数据只采购**有合法授权**的企业级 API，不购买任何"名单"。
- 严禁通过银行、供电、税务等渠道获取非公开数据；严禁跟踪竞争对手车辆、员工。

## 6. 数据可得性：30 条渠道里，哪些真能靠技术 / 付费 API 拿到

> 结论先说：**能全自动、稳定拿到的只有约 1/3，而且大多要靠付费 API 而不是自己爬；约 1/3 只能半自动（人拿到材料、AI 抽取结构化）；剩下 1/3 本质上是"人的渠道"，系统只能做录入、提醒、分成与去重。** 因此每条渠道都要定义四级降级路径：官方 / 付费 API → 合规抓取 → 人工投喂 + AI 抽取 → 纯人工录入。渠道不能因为拿不到接口就从系统里消失。

### 6.1 逐条评估

获取等级：**A** 官方接口或成熟付费 API，稳定；**B** 公开网页可抓，但无接口、有反爬 / 格式杂乱，需持续维护；**C** 只能人工拿到材料（PDF / 截图 / 名录 / 口头），系统做 AI 抽取；**D** 纯人际渠道，系统只做记录与激励；**✗** 不建议获取（法律 / 平台条款风险）。

| # | 渠道 | 等级 | 实际情况 | 拿不到 / 不稳时的替代 |
|---|------|:--:|----------|------------------------|
| P1 | 四库一平台 / 施工许可 | **B→A** | 官方站可公开查询但无开放 API，有验证码、参数加密与频率限制，自建爬虫维护成本高；第三方（建筑工程数据商、工商数据商的"建筑资质 / 项目"模块）已整合并提供 API | 一期直接买第三方 API 按城市订阅；同时接各地住建局"施工许可公示"网页作为免费补充 |
| P2 | 招标 / 中标（含分包） | **A** | 全国几百个公共资源交易站格式各异，自建不现实；招标聚合商（剑鱼、千里马、比地、采招等）有关键词订阅 + API，年费级 | 免费方案：只盯本地 2–3 个交易中心网页 + 邮件 / RSS 订阅；付费后按关键词（钢筋 / 型钢 / 钢结构 / 桩基 / 幕墙 / 暖通）推送 |

### 6.2 拿不到怎么办：四级降级 + 一个统一入口

1. **付费替代自建**：凡是"公开但有反爬"的政务源（四库一平台、招标、工商、许可），一期直接买成熟数据商 API，按目标地级市订阅，自建爬虫只做免费补充。量级参考（需实际询价）：招标聚合订阅约万元级 / 年，工商 API 按调用量计费或包年万元级，建筑工程情报按城市订阅万元级 / 年。相比一个销售的月薪，这是便宜的。
2. **"线索投喂箱"（半自动的统一入口）**：销售 / 运营把任何拿到的材料——政府 PDF、网页链接、名录表格、工地铭牌照片、名片、聊天截图、一段语音——扔进投喂箱，由现有 AI 服务层（复用 `NlTaskParser` 的 JSON Schema 约束输出方式）抽取为项目 / 企业 / 联系人结构化记录，再走实体合并与打分。这是把 C 级渠道全部接入系统的关键，也是本系统 AI 能力最自然的延伸；它让"拿不到 API"不再等于"进不了系统"。
3. **人际渠道系统化**：D 级渠道的数据在人脑里，系统能做的是降低录入成本（介绍人二维码、一键报项目、语音录入）、给激励（分成自动计算与对账）、给弹药（自动生成的本地钢价表、技术资料）、做关联（监理 / 总包名下其他项目提示）。
4. **用能拿到的推断拿不到的**：直接的"要买钢"信号拿不到时，用多信号叠加替代——施工许可 + 桩基分包中标 + 商砼站介绍人确认 = 主体钢筋采购期；环评批复 + 新增钢结构资质 + 焊工招聘 = 新厂投产期。评分模型按信号数量与新鲜度加权。
5. **合规底线不降级**：不爬需登录或条款禁爬的平台（招聘、行业站、竞品）；不买名单与灰色海关数据；政务数据注明来源、按需保留；个人手机号首触即告知来源并提供拒绝方式。

### 6.3 对一期范围的修正

- 适配器实现方式改为"**优先接第三方 API，政务网页抓取为补充**"：P1 / E1 / E2 / E5 走数据商 API；P2 走招标聚合 API（Q11 建议选 B）；E3 走省市数据开放平台接口。
- 新增 **`hdz_acq_intake`（投喂箱）**：附件 / 链接 / 文本 → AI 抽取 → 待确认卡片 → 入库；App 端与后台均可投喂；这一项替代原一期中"P4 / P6 / P7 / P8 各自建适配器"的做法，四条渠道统一走投喂箱 + 少量列表页抓取。
- 招聘信号（E5）与出口数据（E6）从"抓取"改为"数据商字段 + 人工标注"。
- 验收口径补充：投喂箱抽取准确率（建设 / 施工 / 监理单位、面积、日期）≥ 90%；第三方 API 覆盖率按城市抽样核对 ≥ 85%。

## 7. 渠道目录与配置化设计（渠道即配置，拓展不改代码）

### 7.1 原则

- **渠道 = 平台级模板 + 商家级订阅。** 平台维护一份"线索渠道目录"（每条渠道一个配置记录），商家在后台勾选、填参数（地区、关键词、账号 / 密钥）即启用；新增一条同类型渠道只需新增配置，不需要发版。
- **8 种适配器类型覆盖全部 30 条渠道。** 代码层只实现 8 个适配器类型（`LeadSourceAdapter SPI`），渠道差异全部落在配置里：接口地址与鉴权、字段映射、去重键、抽取 Schema、评分参数、合规属性、调度。
- **拿不到就降级，降级也是配置。** 每条渠道可同时挂多个"获取方式"（API → 网页列表 → 投喂箱 → 人工），按优先级启用，运行态自动回退。

### 7.2 适配器类型（代码层，8 个）

| 类型 | 说明 | 配置内容 | 覆盖渠道 |
|------|------|----------|----------|
| `API_PULL` | 定时调用第三方 / 政务开放接口拉取 | 接口地址、鉴权、分页、请求参数模板、JSONPath 字段映射（通用 HTTP 连接器；特殊厂商可挂专用连接器） | P1 / P2 / P5 / P9 / E1 / E2 / E3 / E5（经数据商） |
| `API_PUSH` | 接收第三方推送（Webhook） | 回调地址、签名校验、字段映射 | P2（招标订阅推送）、I2（店铺询盘）、I3（投放线索表单） |
| `WEB_LIST` | 抓公开政务页面列表 + 详情，正文交给 LLM 抽取 | 起始 URL、列表选择器 / 规则、频率、抽取 Schema、robots 与频率约束 | P1（住建局公示，补充）/ P4 / P7 / P8 / E3（无接口地区） |
| `INTAKE` | 投喂箱：人上传 PDF / 链接 / 图片 / 语音 / 文本，AI 抽取为结构化记录 | 抽取 Schema（项目 / 企业 / 联系人）、字段必填、置信度阈值、待确认卡片模板 | P3 / P6 / P8 / E4 / E6 / R6 / F1–F3、任何临时来源 |
| `REFERRAL` | 介绍人渠道：二维码 / 小程序表单报线索，成交后分成 | 介绍人类型、表单字段、分成规则（按吨 / 按金额 / 阶梯）、结算方式 | R1 / R2 / R3 / R4 / R7 |
| `MANUAL` | 销售手工录入（含语音速记、名片 OCR） | 表单模板、必填项 | E7 / R5 / F2 / F3 |
| `INTERNAL_EVENT` | 订阅平台内部事件（站内行为、海报扫码、企微资料变更） | 事件类型、触发阈值（如"7 天内 3 次浏览同规格"） | I4 / R5（企微变更）/ C1–C4 的效果回流 |
| `RPA_CAPTURE` | 执行端抓取（已有一期能力） | 见 05 分册 | I5 |
